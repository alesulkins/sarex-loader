# Публикация предварительного релиза

После коммита выполните `git push origin main`. Сначала запустите ручную проверку Actions по README и изучите результат.

Собрать клиентский архив на Mac из корня проекта:

```sh
.venv/bin/python tools/build_release.py --version v0.1.0-rc.1 --output dist/sarex-loader-v0.1.0-rc.1.zip
```

Архив по умолчанию содержит пустую авторизацию. Если нужно передать именно текущую учётную запись в закрытой поставке, добавьте `--include-account` и используйте другое, ещё не существующее имя ZIP. Конфиг никогда не отправляется в Windows CI. Не размещайте такой архив публично.

GitHub → Releases → Draft a new release → Choose a tag → создайте `v0.1.0-rc.1` от проверенного коммита main. Заголовок: `Sarex Loader v0.1.0-rc.1 — предварительная проверка`. Прикрепите собранный ZIP, отметьте **Set as a pre-release**. Проверьте приватность репозитория перед Publish release. Это не финальная рабочая версия.

Текст для описания релиза:

> Предварительная версия Sarex Loader для проверки СК/ВК. Доступны просмотр назначений PDF, восстановление URL в переданном Excel с резервной копией и офлайн-имитация загрузки на macOS/Linux. Производственная загрузка и создание папок выключены. Для проверки fill используйте копию Excel. Windows: результат ручного CI укажите после его завершения; полная загрузка на Windows ещё не принята. Установите Python 3.11+, распакуйте прикреплённый клиентский ZIP, откройте README и выполните настройку авторизации. Первый запуск требует интернет для установки зависимостей. Не удаляйте SQLite/UNKNOWN и резервные копии.

Не пишите «Windows проверена», пока нет успешного запуска Windows runner. Даже успешный компонентный CI не заменяет приёмку полной цепочки upload. Автоматические Source code архивы GitHub не являются подготовленным клиентским пакетом.
