## Команды и обозначения

Все команды выполняются из распакованной папки программы. Ниже `sk` означает СК; для ВК замените **только `sk` на `vk`**, используйте Excel ВК и корень ВК. Не смешивайте реестры.

| Действие | Windows PowerShell | macOS |
|---|---|---|
| Справка | `.\start.bat -help` | `python3 start.py -help` |
| Офлайн-тест | `.\.venv\Scripts\python.exe tools\mock_demo.py test-offline-01` | `.venv/bin/python tools/mock_demo.py test-offline-01` |
| Настроить аккаунт | `.\start.bat -setup` | `python3 start.py -setup` |
| Проверка назначений | `.\start.bat -preview sk` | `python3 start.py -preview sk` |
| Проверка команды загрузки без отправки | `.\start.bat -load sk --dry-run` | `python3 start.py -load sk --dry-run` |
| Подготовить синтетический PDF для 99-Тест | `.\start.bat -test-pdf` | `python3 start.py -test-pdf` |
| Отправить подготовленный PDF в 99-Тест | `.\start.bat -test-pdf --send ХЕШ_ПЛАНА` | `python3 start.py -test-pdf --send ХЕШ_ПЛАНА` |
| Проверить настройку папок | `.\start.bat -folders status` | `python3 start.py -folders status` |
| Выключить создание папок | `.\start.bat -folders off` | `python3 start.py -folders off` |
| Включить создание месяцев | `.\start.bat -folders on` | `python3 start.py -folders on` |
| Рабочая загрузка | `.\start.bat -load sk` | `python3 start.py -load sk` |
| Рабочая загрузка без перемещения в «не найдено» | `.\start.bat -load sk --no-move` | `python3 start.py -load sk --no-move` |
| Восстановить URL в переданном Excel | `.\start.bat -fill sk` | `python3 start.py -fill sk` |

`ХЕШ_ПЛАНА` замените полным кодом из вывода `-test-pdf`. `--no-move` не запрещает отправку подходящих PDF; для запрета отправки нужен `--dry-run`.

## Порядок тестирования

1. **Подготовка.** Запишите версию, ОС и контрольную сумму ZIP. Установите программу, выполните справку, офлайн-тест и `-setup`. Уточните у заказчика разрешённые папки для реального тестирования. Сам этот документ не разрешает агенту выполнять записи в Sarex.
2. **Изолируйте один пример.** Создайте новую локальную папку, например `Documents\SarexAcceptance\case-01`. Скопируйте туда один PDF, не перемещая оригинал. Сделайте отдельную копию соответствующего Excel и закройте её в Excel. При запуске указывайте эту копию и папку `case-01`, а не папку всей партии. Для следующего сценария используйте новую папку. Для проверки локальных дублей нужны две копии PDF — это отдельное исключение из правила одного файла.
3. **Preview, затем dry-run.** Для каждого примера выполните обе команды. Они спросят путь к копии Excel, папку PDF и корень: СК — `https://lk.sarex.io/documentations/2066367`, ВК — `https://lk.sarex.io/documentations/2067117`. Прочитайте весь путь назначения, ID, даты, номер, подрядчика и причины пропуска. Эти проверки читают реальные метаданные, но не имитируют всю сетевую отправку PDF; дополнительные проверки содержимого и текущего состояния выполняются при рабочем запуске.
4. **99-Тест.** Выполните `-test-pdf`, прочитайте план. После разрешения заказчика выполните `-test-pdf --send ХЕШ_ПЛАНА` и подтвердите отправку. Команда сама создаёт синтетические входные данные; клиентский PDF ей не нужен. Проверьте ссылку в интерфейсе. Повторите отправку с **тем же хешем и журналом**: нового документа быть не должно. Если этот тест уже успешно выполнялся на данном компьютере, повтор проверяет прежний документ; не удаляйте журнал ради получения нового.
5. **Рабочие сценарии.** Только после успешных проверок и отдельного согласования запускайте `-load sk/vk` на папке с одним примером. Это уже реальные изменения выбранного раздела Sarex. Сначала используйте `-folders off`. Прочитайте `ПЛАН.md`; отвечайте `да` только при правильном назначении. Для сценария отсутствующего месяца отдельно включите `-folders on` и подтвердите список создаваемых папок. После проверки снова выполните `-folders off`.
6. **Fill.** Используйте копию Excel. Команда заполняет пустые URL во всей переданной книге выбранного профиля, а не только для одного локального PDF. Папка PDF ей не нужна. Повторите и убедитесь, что заполненные ссылки не перезаписаны.
7. **Зафиксируйте результат.** Для каждого сценария сохраните версию, ОС, команду, имя примера, ожидаемый и фактический результат, пути к отчётам, ID/URL при создании, замечания и решение заказчика. После устранения замечаний заказчик фиксирует результат проверки конкретной версии и согласованного состава функций.

## Сценарии по одному PDF

В таблице «проверка» означает **сначала `-preview sk/vk`, затем `-load sk/vk --dry-run`**. «Загрузка» — `-load sk/vk` после разрешения и подтверждения плана. Во всех положительных примерах должны совпадать дата и номер, быть однозначны офис/подрядчик/строка Excel, отсутствовать дубликаты и ошибки метаданных. Наличие одной строки Excel само по себе не гарантирует загрузку.

| № | Сценарий и данные | Preview и dry-run | Рабочая проверка и ожидаемый результат |
|---|---|---|---|
| 1 | Один корректный новый PDF, одна строка Excel, папка месяца существует | Правильный полный путь и настоящий folder_id, нет блокирующих ошибок | `-folders off`, затем `-load sk/vk` и подтверждение плана. Один PDF в нужном месяце, ID/URL в отчёте, ссылка в переданной копии Excel. Открыть её в Sarex |
| 2 | Корректный PDF, родитель существует, месяца нет | Точное будущее имя, parent_id; выдуманного folder_id нет | `-folders on`, `-load sk/vk`, подтвердить план и отдельно создание. **Первый запуск создаёт только месяц** — проверить `ПАПКИ.md`. **Повторный запуск той же команды** после проверок загружает PDF и сохраняет URL. Папка не должна дублироваться |
| 3 | Месяца нет; создание выключено или пользователь отказывается | Отсутствующий месяц и ожидаемый путь | С `-folders off` предложения создать папку нет. Либо при on ответить `нет` на вопрос создания. Ни папки, ни PDF не создаётся; отказ/пропуск в отчёте, при отказе — в `ПАПКИ.md` |
| 4 | Строка Excel есть, папки подрядчика/офиса нет | Неопределённый маршрут и отсутствующий уровень | Даже при `-folders on` подрядчик/офис автоматически не создаётся, PDF не отправляется. Проверить причину в CSV и журнале |
| 5 | Номера корректно названного PDF нет в Excel, независимо от наличия папки Sarex | Номер не найден; перемещение в «не найдено» только показано | `-load sk/vk`: после подтверждения тестовая копия перемещается в локальную подпапку «не найдено», отправки нет. С `--no-move` файл остаётся на месте. Для двух вариантов использовать отдельные тестовые копии |
| 6 | Конфликт даты Excel/PDF либо некорректное имя/дата PDF | Причина ошибки; при `DATE_MISMATCH` обе даты и предполагаемый месяц по Excel | Достаточно безопасной проверки. PDF не отправляется и не служит основанием для создания месяца; данные автоматически не исправляются. Ошибка разбора имени не равна отсутствию номера в Excel |
| 7 | Несколько подходящих строк Excel, отсутствующие поля или конфликт маршрута | Неоднозначность/недостающие данные, кандидаты и причины | Проверить CSV и журнал. Нет произвольного выбора строки, отправки PDF или создания папки для ошибочного файла |
| 8 | Локальные дубли либо документ уже существует/неоднозначен в Sarex | Выявленные дубли, существующие ID или неоднозначность | Для локальных дублей взять две тестовые копии в отдельную папку. Новых дублей быть не должно. Полный контроль хеша содержимого дополнительно выполняет загрузчик; сетевую отправку дублей проверять офлайн. Если документ уже есть, для пустого URL использовать fill; при неоднозначности ссылка не заполняется |
| 9 | Повтор успешной загрузки №1 на том же компьютере | Уже существующий документ виден в дереве | Повторить тот же `-load sk/vk` с прежним SQLite. Новых отправок 0, документ подтверждён. После ранее неудачного сохранения Excel ссылка может быть восстановлена без повторной загрузки |
| 10 | Fill: пустой URL и однозначный документ; заполненный URL; отсутствующий/неоднозначный документ | Для этого сценария PDF и preview не требуются | `-fill sk/vk` на копии Excel, затем повтор. Однозначный пустой URL заполнен; заполненный не заменён; отсутствующий/неоднозначный остаётся пустым. Проверить Excel, резервную копию, причины по строкам и сохранность остальных данных. Sarex не меняется |
| 11 | Ошибки API, права, неполное дерево, UNKNOWN, сбой сохранения | Ошибка чтения/неполноты блокирует затронутые операции; preview не обещает права на создание | Нестабильные ответы, UNKNOWN и сбои проверять mocks, не провоцировать в Sarex. Явный отказ в создании — сообщение о правах и путь; неопределённый исход — остановка без повтора POST. Журнал и доказательства сохраняются; отсутствие объекта в неполной выдаче не доказывает его отсутствие |

Для отрицательных примеров не портите оригинальный Excel/PDF: берите уже проблемный файл либо используйте отдельную тестовую копию для preview/dry-run. Не подделывайте даты и номера ради реального положительного теста. Для каждого нового примера сначала снова выполните проверку.

## Где сохранять доказательства

- Для каждого запуска программа печатает папку `Downloads/отчет-дата-время`. Открывайте сначала `ИТОГИ.md`, затем подробный Markdown/CSV, после — `журнал.txt`.
- `ПЛАН.md` нужен до подтверждения отправки; путь печатается в терминале. После завершения технический план может находиться в `технические-данные.zip`.
- Результаты создания месяцев — `ПАПКИ.md`; резервные копии Excel находятся отдельно от технического ZIP.
- У 99-Тест свои постоянные входные данные, `registry.test.xlsx`, результаты и SQLite в `.sarex-loader-synthetic-test` в домашней папке пользователя; точные пути выводятся командой.
- Рабочий журнал `.sarex-loader-production-journal` и журнал папок `.sarex-loader-folder-journal` не удалять и не переписывать. Для повторов использовать то же состояние. Не запускать одну партию одновременно на разных компьютерах.

## Готовность к тестированию и ограничения

**Объём партии:** не запускайте сразу папку с тысячами PDF, например 10 000–20 000. Сначала проверьте сценарии по одному PDF, затем используйте отдельные рабочие папки по **100-500 PDF** и так далее повышая объем выборки, каждый раз выполняя preview/dry-run и проверяя итоговый отчёт. Это рекомендация. Точное число файлов, которое «обязательно пройдёт», не установлено, так как результат зависит от данных, объема, маршрутов, прав, сети и Sarex. Уменьшение числа PDF не сокращает рекурсивный обход выбранного корня Sarex; обработка может занять время. Не запускайте одну партию одновременно в нескольких процессах или на разных компьютерах из-за возможной проблемы синхронизации и гонок данных.

Реальное создание папок месяцев ещё не проверялось на сервере из-за ограниченных прав учетной записи. Оно выключено по умолчанию.

При повторяющихся номерах с разными датами ожидается выбор единственной строки по дате PDF. При одинаковых номере и календарной дате у нескольких строк загрузка запрещена независимо от различий офиса и подрядчика.
