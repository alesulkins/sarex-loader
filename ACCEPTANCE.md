## Команды и обозначения

Все команды выполняются из распакованной папки программы. Ниже `sk` означает СК; для ВК замените **только `sk` на `vk`**, используйте Excel ВК и корень ВК. Не смешивайте реестры.

| Действие | Windows PowerShell | macOS |
|---|---|---|
| Справка | `.\start.bat -help` | `python3 start.py -help` |
| Офлайн-тест | `.\.venv\Scripts\python.exe tools\mock_demo.py test-offline-01` | `.venv/bin/python tools/mock_demo.py test-offline-01` |
| Настроить аккаунт | `.\start.bat -setup` | `python3 start.py -setup` |
| Проверка назначений | `.\start.bat -preview sk` | `python3 start.py -preview sk` |
| Проверка команды загрузки без отправки | `.\start.bat -load sk --dry-run` | `python3 start.py -load sk --dry-run` |
| Подготовить синтетический PDF для 99-Тест | `.\start.bat -test-pdf` | `python3 start.py -test-pdf` |
| Отправить подготовленный PDF в 99-Тест | `.\start.bat -test-pdf --send ХЕШ_ПЛАНА` | `python3 start.py -test-pdf --send ХЕШ_ПЛАНА` |
| Проверить настройку папок | `.\start.bat -folders status` | `python3 start.py -folders status` |
| Выключить создание папок | `.\start.bat -folders off` | `python3 start.py -folders off` |
| Включить создание месяцев | `.\start.bat -folders on` | `python3 start.py -folders on` |
| Рабочая загрузка | `.\start.bat -load sk` | `python3 start.py -load sk` |
| Рабочая загрузка без перемещения в «не найдено» | `.\start.bat -load sk --no-move` | `python3 start.py -load sk --no-move` |
| Восстановить URL в переданном Excel | `.\start.bat -fill sk` | `python3 start.py -fill sk` |

`ХЕШ_ПЛАНА` замените полным кодом из вывода `-test-pdf`. `--no-move` не запрещает отправку подходящих PDF; для запрета отправки нужен `--dry-run`.

## Порядок тестирования

1. **Подготовка.** Запишите версию, ОС и контрольную сумму ZIP. Установите программу, выполните справку, офлайн-тест и `-setup`. Уточните у заказчика разрешённые папки для реальной приёмки. Сам этот документ не разрешает агенту выполнять записи в Sarex.
2. **Изолируйте один пример.** Создайте новую локальную папку, например `Documents\SarexAcceptance\case-01`. Скопируйте туда один PDF, не перемещая оригинал. Сделайте отдельную копию соответствующего Excel и закройте её в Excel. При запуске указывайте эту копию и папку `case-01`, а не папку всей партии. Для следующего сценария используйте новую папку. Для проверки локальных дублей нужны две копии PDF — это отдельное исключение из правила одного файла.
3. **Preview, затем dry-run.** Для каждого примера выполните обе команды. Они спросят путь к копии Excel, папку PDF и корень: СК — `https://lk.sarex.io/documentations/2066367`, ВК — `https://lk.sarex.io/documentations/2067117`. Прочитайте весь путь назначения, ID, даты, номер, подрядчика и причины пропуска. Эти проверки читают реальные метаданные, но не имитируют всю сетевую отправку PDF; дополнительные проверки содержимого и текущего состояния выполняются при рабочем запуске.
4. **99-Тест.** Выполните `-test-pdf`, прочитайте план. После разрешения заказчика выполните `-test-pdf --send ХЕШ_ПЛАНА` и подтвердите отправку. Команда сама создаёт синтетические входные данные; клиентский PDF ей не нужен. Проверьте ссылку в интерфейсе. Повторите отправку с **тем же хешем и журналом**: нового документа быть не должно. Если этот тест уже успешно выполнялся на данном компьютере, повтор проверяет прежний документ; не удаляйте журнал ради получения нового.
5. **Рабочие сценарии.** Только после успешных проверок и отдельного согласования запускайте `-load sk/vk` на папке с одним примером. Это уже реальные изменения выбранного раздела Sarex. Сначала используйте `-folders off`. Прочитайте `ПЛАН.md`; отвечайте `да` только при правильном назначении. Для сценария отсутствующего месяца отдельно включите `-folders on` и подтвердите список создаваемых папок. После проверки снова выполните `-folders off`.
6. **Fill.** Используйте копию Excel. Команда заполняет пустые URL во всей переданной книге выбранного профиля, а не только для одного локального PDF. Папка PDF ей не нужна. Повторите и убедитесь, что заполненные ссылки не перезаписаны.
7. **Зафиксируйте результат.** Для каждого сценария сохраните версию, ОС, команду, имя примера, ожидаемый и фактический результат, пути к отчётам, ID/URL при создании, замечания и решение заказчика. После устранения замечаний принимается конкретная версия и согласованный состав функций.

## Сценарии по одному PDF

В таблице «проверка» означает **сначала `-preview sk/vk`, затем `-load sk/vk --dry-run`**. «Загрузка» — `-load sk/vk` после разрешения и подтверждения плана. Во всех положительных примерах должны совпадать дата и номер, быть однозначны офис/подрядчик/строка Excel, отсутствовать дубликаты и ошибки метаданных. Наличие одной строки Excel само по себе не гарантирует загрузку.

| № | Какие данные подготовить | Что должно показать preview и dry-run | Как проверить рабочее поведение | Ожидаемый результат и доказательства |
|---|---|---|---|---|
| 1 | Один новый PDF, ровно одна корректная строка Excel, конечная папка месяца существует | Правильный полный путь и настоящий folder_id; подходящий по метаданным документ | `-folders off`, затем загрузка; подтвердить план | Ровно один новый документ в указанном месяце, подтверждённый ID/URL; URL записан в переданную копию Excel. Проверить отчёт, Excel и ссылку Sarex |
| 2 | Один корректный PDF; родитель «Инспекции» или другой подтверждённый родитель существует, месяца нет | Требуется месячная папка; точное будущее имя, parent_id; выдуманного folder_id нет | `-folders on`, загрузка, подтвердить план и отдельно создание. Затем **повторить загрузку той же командой** с теми же PDF/Excel | Первый запуск: создана только папка, PDF туда ещё не отправлен, результат в `ПАПКИ.md`. Второй: после повторных успешных проверок один PDF загружен и URL сохранён. Проверить место, имя месяца и отсутствие дубля папки |
| 3 | Тот же случай отсутствующего месяца, но создание выключено | Отсутствующий месяц и ожидаемый путь | `-folders off`, загрузка | Ни папки, ни документа не создаётся; файл остаётся на месте, причина пропуска в отчёте; предложения создать папку нет |
| 4 | Строка Excel есть, но нет папки подрядчика или другого необходимого верхнего уровня | Маршрут не подтверждён, показан отсутствующий уровень | Проверка обязательна; при отдельно разрешённой загрузке можно оставить `-folders on` | Никаких автоматических подрядчиков/офисов и PDF; только отчёт об ошибке. Ожидание «ничего» означает отсутствие изменений Sarex, но локальные отчёты будут |
| 5 | Корректное имя PDF, его номера нет в соответствующем Excel; папка Sarex может существовать | Номер не найден; показан план перемещения в «не найдено»; сам PDF не перемещён | Загрузка с подтверждением плана локальных перемещений | В Sarex ничего не записано. Тестовая копия PDF перемещена в `case-XX/не найдено`; подпапка создана при необходимости. Проверить содержимое и журнал |
| 6 | Как №5, но перемещение запрещено | Та же причина отсутствия номера | Загрузка с `--no-move` | Нет отправки и перемещения; PDF остаётся в исходной тестовой папке; причина в отчёте |
| 7 | Дата PDF отличается от Excel | `DATE_MISMATCH`, обе даты, строка Excel; предполагаемый месяц рассчитан по Excel | Достаточно безопасной проверки; отрицательный рабочий запуск только с отдельного разрешения | PDF не отправляется, исходные данные не исправляются. Для конфликтного файла месячная папка не создаётся |
| 8 | Неверная дата/формат имени либо номер нельзя корректно извлечь | Ошибка имени или даты, файл пропущен | Проверка; рабочий запуск только отдельно согласованный | Нет документа и автоматического исправления имени. Не считать ошибку разбора доказательством отсутствия номера в Excel |
| 9 | Несколько подходящих строк Excel для номера | Неоднозначность, кандидаты/причины | Проверка; не выбирать строку вручную через обход защиты | Файл не отправлен, URL произвольной строки не заполнен |
| 10 | Не хватает офиса, подрядчика, даты либо маршрут конфликтует с именем PDF | Конкретная ошибка исходных данных или маршрута | Проверка | Нет отправки и создания папок для ошибочного файла; проверить все причины в CSV |
| 11 | Две локальные копии одной инспекции/одинакового PDF в отдельной папке | Дубли номера/метаданных, если выявлены; совпадение содержимого дополнительно проверяется рабочим загрузчиком | Начать с проверки; тест отправки дублей предпочтительно выполнять офлайн | Не должно появиться двух новых документов. Проверить причины пропуска; preview не объявляется полной проверкой хешей содержимого |
| 12 | PDF уже существует в правильной папке Sarex и не создавался текущим журналом | «Уже есть в Sarex», найденные ID | Загрузка не должна повторять отправку; для пустой ссылки используйте `-fill` на копии Excel | Нового PDF нет. Fill заполняет URL только при однозначном совпадении; факт наличия PDF не означает, что upload обязан восстановить любой старый URL |
| 13 | Повтор успешно выполненного №1 на том же компьютере с прежним журналом | Документ уже виден в дереве | Повторить ту же загрузку, не сбрасывая SQLite | Новых отправок 0; ранее созданный документ подтверждён. При ранее неудачном сохранении ссылки возможна запись подтверждённого URL без повторной загрузки |
| 14 | Несколько подходящих документов Sarex для одной строки | Неоднозначность/дубликаты | Preview/dry-run и fill на копии Excel | Нет новой загрузки; неоднозначный URL остаётся пустым, кандидаты и причина в отчёте |
| 15 | Отсутствующий месяц, создание включено, но пользователь отвечает `нет` | Будущий месяц показан без изменений | Для одного корректного PDF загрузка и отказ на вопросе о создании | Папка и PDF не созданы; отказ зафиксирован в `ПАПКИ.md`; повтор возможен после решения пользователя |

| 17 | Пустой URL, однозначный существующий документ; отдельная строка с заполненным URL | Preview относится к PDF; для этого случая использовать fill | `-fill sk/vk` на тестовой копии Excel, затем повтор | Пустая ссылка заполнена, существующая не изменена; остальные листы/данные сохранены, резервная копия доступна. | 18 | В fill документ или папка отсутствует | Нет однозначного назначения/документа | `-fill sk/vk` на копии | URL остаётся пустым; причина по строке в отчёте. Никаких папок и PDF fill не создаёт |
| 19 | Неполное дерево, ошибка GET, признаки необработанной пагинации, неверный корень | Ошибка данных или отказ проверки | Только безопасная диагностика или синтетический тест | Затронутые операции запрещены; отсутствие объекта в неполной выдаче не считается подтверждённым отсутствием |

## Где сохранять доказательства

- Для каждого запуска программа печатает папку `Downloads/отчет-дата-время`. Открывайте сначала `ИТОГИ.md`, затем подробный Markdown/CSV, после — `журнал.txt`.
- `ПЛАН.md` нужен до подтверждения отправки; путь печатается в терминале. После завершения технический план может находиться в `технические-данные.zip`.
- Результаты создания месяцев — `ПАПКИ.md`; резервные копии Excel находятся отдельно от технического ZIP.
- У 99-Тест свои постоянные входные данные, `registry.test.xlsx`, результаты и SQLite в `.sarex-loader-synthetic-test` в домашней папке пользователя; точные пути выводятся командой.
- Рабочий журнал `.sarex-loader-production-journal` и журнал папок `.sarex-loader-folder-journal` не удалять и не переписывать. Для повторов использовать то же состояние. Не запускать одну партию одновременно на разных компьютерах.

## Готовность к приёмке и ограничения

**Объём партии:** не запускайте сразу папку с тысячами PDF, например 10 000–20 000. Такой объём не прошёл приёмку текущей поставки. Сначала проверьте сценарии по одному PDF, затем используйте отдельные рабочие папки по **10–20 PDF**, каждый раз выполняя preview/dry-run и проверяя итоговый отчёт. Это рекомендация для осторожного начала, а не гарантированный лимит или обещание успешной загрузки каждого файла. Точное число, которое «обязательно пройдёт», не установлено: результат зависит от данных, маршрутов, прав, сети и Sarex. Увеличивать партии можно только после успешной проверки заказчиком. Уменьшение числа PDF не сокращает рекурсивный обход выбранного корня Sarex; обработка может занять время. Не запускайте одну партию одновременно в нескольких процессах или на разных компьютерах.

Программу можно передавать **для контролируемой приёмки по этой инструкции**, начиная с безопасных команд. Это не означает разрешения на массовую загрузку или завершённой приёмки реального создания папок.

Для кода `fee6f78` в [workflow 42112504202](https://github.com/alesulkins/sarex-loader/actions/runs/42112504202) Windows прошла, macOS job отменён без завершения проверки, compare не выполнялся. Локальная чистая установка macOS и сравнение синтетических результатов с Windows прошли. Сценарии CI используют имитацию HTTPS, без клиентских документов и секретов.

Реальное создание месячных папок ещё не принято на сервере. Оно выключено по умолчанию; необходимы права заказчика и согласованная проверка №2. Одна успешная отправка в 99-Тест подтверждает именно этот сценарий, а не все маршруты или права на создание папок. Передача для приёмки допустима; массовая эксплуатация — после принятия результатов заказчиком.

Не передавайте клиентские данные и учётные записи в CI. Не проверяйте сетевые сбои и UNKNOWN намеренными изменениями рабочих разделов Sarex.
