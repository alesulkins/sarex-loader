# Sarex Loader

Загрузка инспекционных PDF в нужные папки Sarex по Excel-реестру и восстановление пустых ссылок `URL` в Excel. СК и ВК обрабатываются **раздельно**. Перед загрузкой можно проверить назначения без изменения Sarex.

Программа работает в терминале. Git, Docker, браузерное расширение и редактирование Python-кода для запуска не нужны. Нужны **Python 3.11+**, интернет и учётная запись Sarex с доступом к соответствующей ветке. Для новой установки используйте обычную сборку Python 3.13/3.14, не embeddable и не free-threaded.

**Текущая поставка: `v0.1.0-rc.7`, для проверки перед приёмкой.** Создание папок выключено. Windows и macOS проверяются раздельно; Linux пока не прошёл нативную приёмку. Сначала выполните справку и офлайн-тест, затем preview. Команды реальной отправки вынесены в конец инструкции.

## Скачать программу

Откройте [Releases Sarex Loader](https://github.com/alesulkins/sarex-loader/releases). В нужном выпуске раскройте **Assets** и выберите архив своей ОС:

| ОС | Файл в Assets |
|---|---|
| Windows | `sarex-loader-v0.1.0-rc.7-windows.zip` |
| macOS | `sarex-loader-v0.1.0-rc.7-macos.zip` |
| Linux — предварительная поддержка | `sarex-loader-v0.1.0-rc.7-linux.zip` |

Эта инструкция не означает, что выпуск уже опубликован. Если этих файлов в Assets ещё нет, получите подготовленный ZIP у разработчика. **Source code (zip)** и **Code → Download ZIP** — архивы репозитория, а не минимальная поставка. Для приватного репозитория нужен доступ к GitHub; полученный напрямую клиентский ZIP можно запускать без GitHub-аккаунта.

Выберите **один** раздел установки ниже. После установки порядок действий одинаков на всех ОС.

## 1. Установка

### Windows

**Python.** Откройте [официальную страницу Python для Windows](https://www.python.org/downloads/windows/). Для обычного компьютера Intel/AMD скачайте **Windows installer (64-bit)** версии 3.14; для ARM-компьютера нужен отдельный ARM64-установщик, эта конфигурация пока не прошла нашу приёмку. В установщике отметьте **Add python.exe to PATH**, затем **Install Now**. Закройте и заново откройте PowerShell.

Если удобнее скачать установщик командой, следующий пример получает официальный Python 3.14.10 для Intel/AMD и открывает обычный мастер установки:

```powershell
$installer = Join-Path $env:USERPROFILE "Downloads\python-3.14.10-amd64.exe"
Invoke-WebRequest "https://www.python.org/ftp/python/3.14.10/python-3.14.10-amd64.exe" -OutFile $installer
Start-Process -FilePath $installer -Wait
```

Проверьте в новом PowerShell:

```powershell
python --version
```

Если вместо версии открывается Microsoft Store, используйте `py -3 --version`. После установки нескольких Python выберите нужный интерпретатор; не меняйте системные настройки вслепую.

**Sarex Loader.** Скачайте Windows ZIP в «Загрузки». Нажмите правой кнопкой → **Извлечь всё**. Перенесите распакованную папку в «Документы», например в `Documents\SarexLoader`. Внутри должны быть `start.bat`, `start.py`, `README.md` и `src`. Не запускайте файлы прямо внутри ZIP.

Можно распаковать командой в новую папку (для обновления используйте другую папку, не перезаписывайте прежнюю):

```powershell
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\sarex-loader-v0.1.0-rc.7-windows.zip" -DestinationPath "$env:USERPROFILE\Documents\SarexLoader-rc7"
Set-Location "$env:USERPROFILE\Documents\SarexLoader-rc7\sarex-loader-v0.1.0-rc.7-windows"
.\start.bat -help
```

При ручной распаковке откройте папку со `start.bat` в Проводнике, нажмите адресную строку, напишите `powershell`, нажмите Enter. Затем выполните ` .\start.bat -help `.

Первый запуск создаёт `.venv` и скачивает зависимости. Нужен интернет; дождитесь справки. **Активировать `.venv` и менять ExecutionPolicy не нужно.** При проблеме с BAT можно запустить `py -3 start.py -help`. Для меню — дважды нажать `start.bat` или выполнить ` .\start.bat ` без аргументов.

### macOS

**Python.** Скачайте обычный `.pkg` Python 3.14 с [python.org для macOS](https://www.python.org/downloads/macos/). Откройте установщик и пройдите мастер. Затем в «Программы → Python 3.14» запустите **Install Certificates.command** — это штатный шаг установки сертификатов. [Инструкция Python](https://docs.python.org/3/using/mac.html).

Те же действия с загрузкой официального установщика через Терминал:

```sh
curl -fL https://www.python.org/ftp/python/3.14.10/python-3.14.10-macos11.pkg -o "$HOME/Downloads/python-3.14.10-macos11.pkg"
open "$HOME/Downloads/python-3.14.10-macos11.pkg"
```

После завершения мастера:

```sh
open "/Applications/Python 3.14/Install Certificates.command"
python3 --version
```

Если Homebrew уже установлен, вместо `.pkg` можно использовать `brew install python@3.13`, а для первого запуска — `python3.13 start.py -help`. [Описание пакета Homebrew](https://formulae.brew.sh/formula/python@3.13). Достаточно одного способа установки Python.

**Sarex Loader.** Скачайте macOS ZIP, дважды нажмите его в Finder и перенесите полученную папку в «Документы». Откройте «Терминал», напишите `cd ` с пробелом, перетащите **папку** из Finder в окно терминала и нажмите Enter. Затем:

```sh
python3 start.py -help
```

Либо распакуйте и откройте конкретный архив командами:

```sh
mkdir -p "$HOME/Documents/SarexLoader-rc7"
unzip "$HOME/Downloads/sarex-loader-v0.1.0-rc.7-macos.zip" -d "$HOME/Documents/SarexLoader-rc7"
cd "$HOME/Documents/SarexLoader-rc7/sarex-loader-v0.1.0-rc.7-macos"
python3 start.py -help
```

Первый запуск создаёт `.venv` и устанавливает зависимости. Для меню выполните `python3 start.py` без аргументов. Дополнительный ярлык `start.command` запускает то же меню; если Finder не позволяет его открыть, используйте команду выше, не отключая защиту macOS.

### Linux

Нативная проверка Linux ещё не проведена. Начинайте с офлайн-теста; этот архив пока нельзя считать принятой Linux-версией.

Для Ubuntu 24.04+ / Debian 12+ откройте Терминал и установите Python, модуль виртуальных окружений и unzip:

```sh
sudo apt update
sudo apt install python3 python3-venv python3-pip unzip
python3 --version
```

Нужна версия не ниже 3.11. Для других дистрибутивов используйте их пакетный менеджер. Не запускайте Loader через `sudo`. [Инструкция Ubuntu по Python](https://ubuntu.com/developers/docs/howto/python-setup/).

Скачайте Linux ZIP через браузер в `Downloads`, затем:

```sh
mkdir -p "$HOME/Documents/SarexLoader-rc7"
unzip "$HOME/Downloads/sarex-loader-v0.1.0-rc.7-linux.zip" -d "$HOME/Documents/SarexLoader-rc7"
cd "$HOME/Documents/SarexLoader-rc7/sarex-loader-v0.1.0-rc.7-linux"
python3 start.py -help
```

Если папка загрузок у вас называется иначе, замените путь. Дальнейшие команды Linux совпадают с macOS.

## 2. Проверка без учётной записи и без Sarex

Все команды ниже выполняйте **из распакованной папки программы**. Не переносите отдельный `start.py`/`start.bat` без остальных файлов.

Сначала `-help`, затем офлайн-тест:

| Действие | Windows PowerShell | macOS | Linux |
|---|---|---|---|
| Справка | `.\start.bat -help` | `python3 start.py -help` | `python3 start.py -help` |
| Офлайн-тест | `.\.venv\Scripts\python.exe tools\mock_demo.py test-offline-01` | `.venv/bin/python tools/mock_demo.py test-offline-01` | `.venv/bin/python tools/mock_demo.py test-offline-01` |

Офлайн-тест **не подключается к Sarex**, не требует аккаунта и сам создаёт синтетические PDF, Excel и отдельный SQLite. Ожидаемый результат: **1 новый синтетический документ, 2 дубликата пропущены, повторных отправок 0**. В папке `test-offline-01` появятся входные данные, результаты первого/повторного запуска, новый mock-журнал и `result.json`. Это имитация, а не реальная загрузка.

При повторной независимой проверке укажите новое имя, например `test-offline-02`. Не используйте существующий каталог и пути с `..`.

**Для первой проверки у другого человека достаточно этих двух команд.** Учётная запись и клиентские документы не нужны. Отправьте разработчику версию Python, текст ошибки при её наличии и `result.json`.

## 3. Вход в Sarex

| Windows | macOS | Linux |
|---|---|---|
| `.\start.bat -setup` | `python3 start.py -setup` | `python3 start.py -setup` |

Программа спросит **логин**, затем **пароль**. При вводе пароля символы и звёздочки не отображаются — введите его и нажмите Enter. Права программы соответствуют введённой учётной записи Sarex.

Настройки сохраняются в `account.toml` рядом с программой; вручную редактировать логин/пароль не нужно. Для смены аккаунта снова запустите `-setup`. При первом `-preview`, `-fill` или `-test-pdf` настройка предложится автоматически; перед `-load` выполните `-setup` отдельно. Справка и офлайн-тест авторизацию не требуют.

Архив содержит пустой конфиг. Заполненный `account.toml` содержит пароль — не отправляйте его вместе с отчётами и не публикуйте. Создание папок оставьте выключенным.

## 4. Подготовьте данные и проверьте назначения

- Нужен реальный реестр `.xlsx` со столбцами `ID`, `Дата`, `П_Офис`, `Подрядчик`, `Номер`, `URL`. Закройте книгу в Excel. Файл `~$Инспекции…xlsx` — временный, его выбирать нельзя.
- СК и ВК — отдельные реестры и отдельные папки PDF. Обрабатываются PDF **непосредственно в выбранной папке**, без обхода подпапок. Для второй папки PDF сделайте отдельный запуск.
- В OneDrive выберите «Всегда хранить на этом устройстве» и дождитесь скачивания. Требуется локальный путь, веб-ссылка на OneDrive не подходит.
- Храните Excel и PDF отдельно от программы и отчётов. Например, программа — `Documents\SarexLoader`, данные — `Documents\SarexData`, отчёты — по умолчанию `Downloads`.
- В Windows скопируйте файл через «Копировать как путь»; внешние двойные кавычки допустимы. На macOS можно перетащить файл/папку в окно терминала и проверить получившийся путь. Если терминал добавил `\` перед пробелами, при ответе на вопрос программы вставьте обычный полный путь без этих экранирующих слешей. После `.xlsx` не ставьте `/` или `\`.

| Режим | Windows | macOS | Linux |
|---|---|---|---|
| Проверить СК | `.\start.bat -preview sk` | `python3 start.py -preview sk` | `python3 start.py -preview sk` |
| Проверить ВК | `.\start.bat -preview vk` | `python3 start.py -preview vk` | `python3 start.py -preview vk` |
| Проверить загрузку СК без отправки | `.\start.bat -load sk --dry-run` | `python3 start.py -load sk --dry-run` | `python3 start.py -load sk --dry-run` |
| Проверить загрузку ВК без отправки | `.\start.bat -load vk --dry-run` | `python3 start.py -load vk --dry-run` | `python3 start.py -load vk --dry-run` |

Вопросы по порядку:

| № | Вопрос | Пример ответа |
|---|---|---|
| 1 | Полный путь к Excel соответствующего реестра | Windows: `C:\Users\Anna\Documents\SarexData\Инспекции СК.xlsx`; macOS: `/Users/anna/Documents/SarexData/Инспекции СК.xlsx`; Linux: `/home/anna/Documents/SarexData/Инспекции СК.xlsx` |
| 2 | Локальная папка PDF | Путь к папке СК или ВК на этом компьютере |
| 3 | Ссылка на корень Sarex | СК: `https://lk.sarex.io/documentations/2066367`; ВК: `https://lk.sarex.io/documentations/2067117` |

Папку отчётов вводить не нужно — она создаётся автоматически. Программа читает структуру выбранного корня, проверяет Excel/PDF и формирует отчёт. `-preview` и `-load … --dry-run` **не создают папки/документы Sarex, не меняют Excel и не перемещают PDF**. Планируемое перемещение в «не найдено» только показывается. Это проверка реальных назначений; имитация POST выполняется отдельным офлайн-тестом.

Для проверки одинаковой маршрутизации на двух компьютерах используйте одинаковые реестры, PDF, версию программы и сопоставимые снимки дерева. Сравнивайте по каждому файлу статус, полный путь и `folder_id`, а не только общие количества.

## 5. Восстановление ссылок в Excel

Сначала сделайте копию Excel и укажите её при первом запуске. PDF для этой команды не нужны.

| Windows | macOS | Linux |
|---|---|---|
| `.\start.bat -fill sk` | `python3 start.py -fill sk` | `python3 start.py -fill sk` |
| `.\start.bat -fill vk` | `python3 start.py -fill vk` | `python3 start.py -fill vk` |

Вопросы: **путь к Excel → ссылка на корень СК/ВК**. Программа читает Sarex и записывает найденные однозначные URL **в переданный Excel**. Отдельного вопроса «разрешить запись» у `-fill` нет. Уже заполненные ссылки не заменяются; остальные листы и оформление сохраняются в пределах поддерживаемого формата Excel. Сложные расширения Excel требуют отдельной проверки на копии.

Перед сохранением создаётся резервная копия, запись выполняется через временный файл и проверяется на диске. При отсутствии документа, неоднозначности или ошибке маршрута URL остаётся пустым. В Sarex эта команда ничего не изменяет.

## 6. Где находятся результаты

После preview/dry-run, fill или load откройте путь, напечатанный в терминале. По умолчанию это папка `Downloads/отчет-ГГГГ-ММ-ДД-ЧЧ-ММ-СС` в вашем профиле пользователя; при совпадении времени добавляется суффикс.

```text
отчет-2026-11-05-18-30-00/
├── ИТОГИ.md                   ← открыть первым: статистика и ссылки
├── PDF_UPLOAD_PREVIEW.md      ← для проверки PDF: назначения и причины
├── pdf_upload_preview.csv     ← подробная таблица PDF
├── …другие отчёты режима      ← для fill: результаты поиска URL по строкам
├── журнал.txt                 ← подробный ход работы и ошибки
├── технические-данные.zip     ← снимок дерева, планы, checkpoint, диагностика
└── резервные копии Excel/     ← при сохранении Excel; не прячутся в ZIP
```

Набор подробных отчётов зависит от команды. Markdown можно читать в Блокноте/TextEdit или редакторе с предпросмотром, CSV — в Excel. Если CSV отображается неверно, импортируйте его как UTF-8. Консоль показывает короткий итог и пути, подробности находятся в журнале.

При незавершённом запуске папка `технические данные` остаётся **неупакованной**, чтобы сохранить checkpoint. Не удаляйте её. Для продолжения обхода добавьте `--resume` и путь к checkpoint из журнала:

| Windows | macOS | Linux |
|---|---|---|
| `.\start.bat -preview sk --resume "C:\путь\к\checkpoint"` | `python3 start.py -preview sk --resume "/путь/к/checkpoint"` | `python3 start.py -preview sk --resume "/путь/к/checkpoint"` |

Вводите прежние реестр, папку и корень. Здесь нужен каталог checkpoint, не ZIP. Для обычного нового запуска `--resume` не нужен.

При желании задайте базовую папку отчётов в начале `account.toml`, **до любых секций `[auth]` и других**:

```toml
# Windows — пример; выберите свою отдельную папку
results_dir = 'C:\SarexResults'
# Для macOS вместо строки выше: results_dir = '/Users/anna/SarexResults'
# Для Linux вместо строки выше: results_dir = '/home/anna/SarexResults'
```

Оставьте только одну активную строку `results_dir`. Каталог программа создаст сама. Отчёты нельзя размещать внутри папок исходных Excel/PDF. Без этой настройки используется `Downloads`.

## 7. Тестовая загрузка в 99-Тест — только после согласования

Это уже работа с настоящим Sarex. Для проверки у сестры без записей достаточно разделов 2–5; команды `--send` и рабочий `-load` не нужны.

| Действие | Windows | macOS | Linux |
|---|---|---|---|
| Подготовить синтетический PDF и проверить цель, без отправки | `.\start.bat -test-pdf` | `python3 start.py -test-pdf` | `python3 start.py -test-pdf` |
| Отправить подготовленный PDF | `.\start.bat -test-pdf --send ХЕШ_ПЛАНА` | `python3 start.py -test-pdf --send ХЕШ_ПЛАНА` | `python3 start.py -test-pdf --send ХЕШ_ПЛАНА` |

Первая команда использует сохранённую учётную запись, читает метаданные и создаёт локальные синтетические PDF/Excel. Пути к клиентским файлам не запрашиваются. Цель фиксирована: `99-Тест`, корень **2093037**, конечная папка **7915046**. Перенаправить тест в 00-ТехЗак нельзя.

После отдельного разрешения замените `ХЕШ_ПЛАНА` полным SHA-256 из **своего текущего вывода**. Во второй команде дополнительно ответьте `да` на вопрос об отправке. Проверяется не более одного закреплённого PDF. Успешный результат содержит ID и URL, ссылка сохраняется в новую тестовую книгу `registry.test.xlsx`.

Повтор той же команды с тем же хешем и сохранённым журналом должен проверить уже созданный документ без повторной загрузки. Не удаляйте состояние для получения нового теста. Неопределённый результат POST запрещает повтор.

Состояние теста: Windows `%USERPROFILE%\.sarex-loader-synthetic-test`, macOS/Linux `~/.sarex-loader-synthetic-test`. Внутри `input` — синтетические файлы, `manifest.json` — план, `journal` — SQLite, `result-*` — отчёты отдельных запусков. Точный путь печатается в терминале.

## 8. Рабочая загрузка СК/ВК — после проверки плана и приёмки

**Эти команды могут создавать документы в 00-ТехЗак.** Для просмотра без отправки используйте `--dry-run` из раздела 4.

| Windows | macOS | Linux |
|---|---|---|
| `.\start.bat -load sk` | `python3 start.py -load sk` | `python3 start.py -load sk` |
| `.\start.bat -load vk` | `python3 start.py -load vk` | `python3 start.py -load vk` |

Вопросы: **Excel → папка PDF → корень Sarex**. Затем программа готовит `ПЛАН.md` и SHA-256 плана, показывает их расположение и запрашивает подтверждение. Откройте план и проверьте пути и ID. Ответ `нет` отменяет отправку. До `да` исходные PDF/Excel и Sarex не изменяются, но локальные отчёты и журнал могут быть созданы.

После `да` программа проверяет цели и дубликаты, последовательно загружает разрешённые PDF, подтверждает результат GET и записывает URL **в переданный исходный Excel** с резервной копией. Ошибочные PDF пропускаются с причинами. Новые месячные папки не создаются и не предлагаются к созданию.

Только файлы с доказанно отсутствующим в Excel номером перемещаются в локальную подпапку **«не найдено»** выбранной папки PDF. Она создаётся автоматически при необходимости. Для запрета этих перемещений добавьте `--no-move`, например ` .\start.bat -load sk --no-move `. Это не отменяет разрешённую загрузку остальных файлов.

Рабочее состояние хранится вне папки программы: Windows `%USERPROFILE%\.sarex-loader-production-journal`, macOS/Linux `~/.sarex-loader-production-journal`. Это постоянный SQLite-журнал и блокировки для обоих профилей. **Не удаляйте, не сбрасывайте и не подменяйте его.** При созданном документе и неудачном сохранении Excel повтор восстанавливает URL без нового POST; при `OUTCOME_UNKNOWN` обратитесь к разработчику.

`Ctrl+C` во время отправки запрашивает остановку после текущего PDF и сохранения состояния. Дождитесь завершения; не закрывайте терминал принудительно. Не обрабатывайте одну партию одновременно на разных компьютерах: их локальные журналы не синхронизированы.

## 9. Состав папки и обновление

Минимальная поставка содержит:

```text
sarex-loader-v0.1.0-rc.7-<платформа>/
├── README.md                  ← эта инструкция
├── start.bat                  ← только Windows
├── start.command              ← только macOS, дополнительный ярлык
├── start.py                   ← общий запуск и автоматическая установка
├── account.toml               ← пустой при поставке; ваш аккаунт после -setup
├── customer.routes.toml       ← служебная конфигурация поставки
├── pyproject.toml             ← версия и зависимости Python
├── MANIFEST.in                ← состав устанавливаемого пакета
├── src/sarex_loader/           ← код, внутренние правила маршрутов и ресурсы
└── tools/mock_demo.py          ← безопасная офлайн-проверка
```

Не удаляйте файлы внутри `src`: там находятся проверки безопасности и общие компоненты. Файл `profile-routes.toml` внутри пакета содержит рабочие правила; самостоятельное изменение `customer.routes.toml` не меняет маршрутизацию коротких команд.

После первого запуска дополнительно появляются `.venv` и иногда служебные `build`, `*.egg-info`, `__pycache__` — результаты установки Python. Их нет в исходном ZIP. Ничего переносить из них на другую ОС не нужно. SQLite-состояние и отчёты находятся в местах, описанных выше.

При обновлении распакуйте новую версию **в отдельную папку**, выполните `-help`, офлайн-тест и `-setup`. Не копируйте старую `.venv` и не удаляйте журналы из профиля пользователя. После обновления повторите preview. Для передачи другому человеку используйте исходный клиентский ZIP с пустым аккаунтом, а не свою уже настроенную папку.

## 10. Частые вопросы

| Ситуация | Что сделать |
|---|---|
| `start.bat` / `start.py` не найден | Открыть терминал в папке с этими файлами, а не на уровень выше и не внутри ZIP |
| Python не найден / слишком старый | Установить Python по разделу 1, открыть новый терминал; на Windows проверить `py -3 --version` |
| Ошибка установки зависимостей | Проверить интернет и право записи в папку программы; повторить `-help`. Не устанавливать в Program Files |
| Ошибка HTTPS на macOS | Для Python с python.org выполнить Install Certificates.command; не отключать TLS |
| Не удалось сохранить Excel | Закрыть книгу и проверить права; сохранить отчёт, резервную копию и журнал |
| Папка не найдена | Проверить путь в отчёте. Отсутствующую папку создаёт уполномоченный пользователь Sarex, затем повторяется preview |
| Дата PDF не совпадает с Excel | Маршрут показан по Excel, загрузка блокируется. Исправление клиентских данных автоматически не выполняется |
| Несколько совпадений / дубликаты | Документ пропускается; проверить строки Excel и реальные документы, не выбирать произвольный вариант |
| `OUTCOME_UNKNOWN` | Не повторять отправку и не удалять журнал; передать диагностику разработчику |
| Где посмотреть ошибки? | Сначала ИТОГИ.md, затем подробный отчёт/CSV, после — журнал.txt |
| Как проверить без изменения Sarex? | Офлайн-тест без аккаунта; с аккаунтом — preview/dry-run; fill не меняет Sarex, но изменяет указанный Excel |

Завершённый обход Gateway принят как практически достаточный источник. Это не абсолютная гарантия полноты API. Конкретные ошибки GET, непроверенные ветки, признаки обрезанной выдачи, конфликтующие номера/даты и неоднозначные назначения остаются причинами пропуска.
