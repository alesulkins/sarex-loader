# Sarex Loader

Загрузка инспекционных PDF в нужные папки Sarex по Excel-реестру и восстановление пустых ссылок `URL` в Excel. СК и ВК обрабатываются **раздельно**. Перед загрузкой можно проверить места назначения файлов и папок без изменения файловой структуры Sarex.

Программа работает в терминале. Нужны **Python 3.11 и выше**, интернет и учётная запись в Sarex.
Для новой установки Python используйте обычную сборку Python 3.13/3.14.

## 1. Установка

### Windows

**Python**

1. Откройте [официальную страницу Python для Windows](https://www.python.org/downloads/windows/).
2. Для Intel/AMD скачайте **Windows installer (64-bit)** [версии 3.14](https://www.python.org/ftp/python/3.14.10/python-3.14.10-amd64.exe).
3. В установщике отметьте **Add python.exe to PATH**, затем **Install Now**. Закройте и заново откройте PowerShell.

**Либо** если удобнее скачать установщик командой (ничего заменять не нужно: `$env:USERPROFILE` автоматически обозначает вашу папку пользователя):

```powershell
$installer = Join-Path $env:USERPROFILE "Downloads\python-3.14.10-amd64.exe"
Invoke-WebRequest "https://www.python.org/ftp/python/3.14.10/python-3.14.10-amd64.exe" -OutFile $installer
Start-Process -FilePath $installer -Wait
```

Проверьте в новом PowerShell:

```powershell
python --version
```

**Sarex Loader**

1. Скачайте Windows ZIP в «Загрузки».
2. Нажмите правой кнопкой → **Извлечь всё**.
3. Перенесите распакованную папку в «Документы», например в `Documents\SarexLoader`.

Можно распаковать командой в другую папку (ничего заменять не нужно: `$env:USERPROFILE` автоматически обозначает вашу папку пользователя):

```powershell
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\sarex-loader-v0.1.0-rc.8-windows.zip" -DestinationPath "$env:USERPROFILE\Documents\SarexLoader-rc8"
Set-Location "$env:USERPROFILE\Documents\SarexLoader-rc8\sarex-loader-v0.1.0-rc.8-windows"
.\start.bat -help
```

При ручной распаковке найдите **папку `sarex-loader-v0.1.0-rc.8-windows`**. Нужна именно эта папка, а не ZIP и не внешняя папка, в которую его распаковали.

Нажмите **Win+R**, введите `powershell` и нажмите Enter — откроется окно для ввода команд. Введите `cd "полный путь к папке sarex-loader-v0.1.0-rc.8-windows"`, заменив текст в кавычках своим путём. Например, если перенесли папку в «Документы»:

```powershell
cd "$env:USERPROFILE\Documents\sarex-loader-v0.1.0-rc.8-windows"
.\start.bat -help
```

Здесь заменять путь нужно **только если вы сохранили программу в другом месте**. Все следующие команды запускайте в этом окне.

Первый запуск создаёт `.venv` и скачивает зависимости.
Нужен интернет; дождитесь справки.
**Активировать `.venv` и менять ExecutionPolicy не нужно.**
При проблеме с BAT можно запустить `py -3 start.py -help`.
Для меню — дважды нажать `start.bat` или выполнить ` .\start.bat ` без аргументов.

### macOS

**Python**

1. Скачайте `.pkg` Python 3.14 с [python.org для macOS](https://www.python.org/downloads/macos/).
2. Откройте установщик и пройдите мастер.

```sh
open "$HOME/Downloads/python-3.14.10-macos11.pkg"
```


Если Homebrew уже установлен, вместо `.pkg` можно использовать `brew install python@3.13`, а для первого запуска — `python3.13 start.py -help`.
[Описание пакета Homebrew](https://formulae.brew.sh/formula/python@3.13). Достаточно одного способа установки Python.

**Sarex Loader.**

2. Откройте «Терминал», напишите `cd ` (с пробелом), перетащите **папку** из Finder в окно терминала и нажмите Enter. Затем:

```sh

```

Либо распакуйте и откройте конкретный архив командами:

```sh
unzip "$HOME/Downloads/sarex-loader-v0.1.0-rc.8-macos.zip" -d "$HOME/Documents/SarexLoader-rc8"
cd "$HOME/Documents/SarexLoader-rc8/sarex-loader-v0.1.0-rc.8-macos"
python3 start.py -help
```

Первый запуск создаёт `.venv` и устанавливает зависимости.

Дополнительный ярлык `start.command` запускает то же меню; если Finder не позволяет его открыть, используйте команду выше, не отключая защиту macOS.


## 2. Проверка без учётной записи и без Sarex

Все команды ниже выполняйте **из распакованной папки своей ОС**: `sarex-loader-v0.1.0-rc.8-windows` или `sarex-loader-v0.1.0-rc.8-macos`. Не переносите `start.py`/`start.bat` отдельно.

Сначала `-help`, затем офлайн-тест:

| Действие | Windows PowerShell | macOS |
|---|---|---|
| Справка | `.\start.bat -help` | `python3 start.py -help` |
| Офлайн-тест | `.\.venv\Scripts\python.exe tools\mock_demo.py test-offline-01` | `.venv/bin/python tools/mock_demo.py test-offline-01` |

Офлайн-тест **не подключается к Sarex**, не требует аккаунта и сам создаёт синтетические PDF, Excel и отдельный SQLite.
Ожидаемый результат: **1 новый синтетический документ, 2 дубликата пропущены, повторных отправок 0**.
В папке `test-offline-01` появятся входные данные, результаты первого/повторного запуска, новый mock-журнал и `result.json`. Это имитация, а не реальная загрузка.

При повторной независимой проверке укажите новое имя, например `test-offline-02`. Программа сама создаст эту тестовую папку рядом с собой. Имя должно быть новым, чтобы не перезаписать прошлые результаты. Указывайте простое имя, например `test-offline-02`, без слешей и без `..` (обозначение перехода в родительскую папку).

## 3. Вход в Sarex

| Windows | macOS |
|---|---|
| `.\start.bat -setup` | `python3 start.py -setup` |

Программа спросит **логин**, затем **пароль**. При вводе пароля символы и звёздочки не отображаются — введите или вставьте его и нажмите Enter. Права программы соответствуют введённой учётной записи Sarex.

Настройки сохраняются в `account.toml` рядом с программой; вручную редактировать логин/пароль не нужно.
Для смены аккаунта запустите `-setup`.
При первом `-preview`, `-fill` или `-test-pdf` настройка предложится автоматически.
Перед `-load` выполните `-setup` отдельно.
Справка и офлайн-тест авторизацию не требуют.

## 4. Подготовьте данные и проверьте назначения

- Нужен реестр `.xlsx` со столбцами `ID`, `Дата`, `П_Офис`, `Подрядчик`, `Номер`, `URL`. Закройте книгу в Excel.
- СК и ВК — отдельные папки PDF. Обрабатываются PDF **непосредственно в выбранной папке**, без обхода подпапок. Для второй папки PDF сделайте отдельный запуск.
- В OneDrive выберите «Всегда хранить на этом устройстве» и дождитесь скачивания. Требуется локальный путь, веб-ссылка на OneDrive не подходит.
- Храните Excel и PDF отдельно от программы и отчётов. Например, программа — `Documents\SarexLoader`, данные — `Documents\SarexData`, отчёты — по умолчанию `Downloads` (можно поменять расположение).
- В Windows скопируйте путь до файла через «Копировать как путь».
- На macOS можно перетащить файл/папку в окно терминала и проверить получившийся путь. Если терминал добавил `\` перед пробелами, при ответе на вопрос программы вставьте обычный полный путь без экранирующих слешей. После `.xlsx` не ставьте `/` или `\`.

| Режим | Windows | macOS |
|---|---|---|
| Проверить СК без отправки в СОД| `.\start.bat -preview sk` | `python3 start.py -preview sk` |
| Проверить ВК без отправки в СОД| `.\start.bat -preview vk` | `python3 start.py -preview vk` |
| Проверить загрузку СК без отправки в СОД| `.\start.bat -load sk --dry-run` | `python3 start.py -load sk --dry-run` |
| Проверить загрузку ВК без отправки в СОД| `.\start.bat -load vk --dry-run` | `python3 start.py -load vk --dry-run` |

- **`-preview sk`** — сопоставляет PDF СК с Excel СК, проверяет папки и документы Sarex и показывает, что можно загрузить и что будет пропущено.
- **`-preview vk`** — такая же проверка для PDF и Excel ВК.
- **`-load sk --dry-run`** — безопасный проверочный запуск команды загрузки СК. Сейчас выполняет ту же проверку, что `-preview sk`, без отправки файлов.
- **`-load vk --dry-run`** — такой же проверочный запуск для ВК.

Все четыре команды создают только локальные отчёты. PDF, Excel и Sarex остаются без изменений.

Вопросы по порядку:

| № | Вопрос | Пример ответа |
|---|---|---|
| 1 | Полный путь к Excel соответствующего реестра | Windows: `C:\Users\incognito\Documents\SarexData\Инспекции СК.xlsx`; macOS: `/Users/anna/Documents/SarexData/Инспекции СК.xlsx`; Linux: `/home/incognito/Documents/SarexData/Инспекции СК.xlsx` |
| 2 | Локальная папка PDF | Путь к папке СК или ВК на этом компьютере |
| 3 | Ссылка на корень Sarex | СК: `https://lk.sarex.io/documentations/2066367`; ВК: `https://lk.sarex.io/documentations/2067117` |

Папка отчётов создаётся автоматически. Программа читает структуру выбранного корня, проверяет Excel/PDF и формирует отчёт.
`-preview` и `-load … --dry-run` **не создают папки/документы Sarex, не меняют Excel и не перемещают PDF**.
Если номера PDF нет в Excel, отчёт покажет: при рабочей загрузке этот файл попадёт в локальную подпапку «не найдено». Во время проверки файл остаётся на месте. Проверка использует настоящие данные Excel/PDF и структуру Sarex, но не пробует отправлять документы. Сам процесс отправки без подключения к Sarex проверяет офлайн-тест из раздела 2.

## 5. Восстановление ссылок в Excel
При тестировании используйте копию таблицы инспекций.

| Windows | macOS |
|---|---|
| `.\start.bat -fill sk` | `python3 start.py -fill sk` |
| `.\start.bat -fill vk` | `python3 start.py -fill vk` |

Вопросы:
**путь к Excel → ссылка на корень СК/ВК**.
Программа читает Sarex и записывает найденные однозначные URL **в переданный Excel**. Отдельного вопроса «разрешить запись» у `-fill` нет.
Уже заполненные ссылки не заменяются.

Перед изменением программа сохраняет резервную копию Excel — её можно использовать для восстановления. Обновлённую книгу сначала записывает в отдельный временный файл и только после проверки заменяет переданный Excel. Успешное сохранение проверяется повторным чтением с диска. Если документ не найден, найдено несколько подходящих документов или не определена нужная папка, ссылка остаётся пустой, а причина попадает в отчёт. **Меняется только ваш локальный Excel; файлы и папки Sarex не меняются.**

## 6. Где находятся результаты

После preview/dry-run, fill или load откройте путь, напечатанный в терминале.
По умолчанию это папка `Downloads/отчет-ГГГГ-ММ-ДД-ЧЧ-ММ-СС`.

```text
отчет-2026-11-05-18-30-00/
├── ИТОГИ.md                   ← открыть первым: статистика и ссылки
├── PDF_UPLOAD_PREVIEW.md      ← для проверки PDF: назначения и причины
├── pdf_upload_preview.csv     ← подробная таблица PDF
├── …другие отчёты режима      ← для fill: результаты поиска URL по строкам
├── журнал.txt                 ← подробный ход работы и ошибки
├── технические-данные.zip     ← снимок дерева, планы, checkpoint, диагностика
└── резервные копии Excel/     ← при сохранении Excel; не прячутся в ZIP
```

Набор подробных отчётов зависит от команды.
Markdown можно читать в Блокноте/TextEdit, но удобнее всего в редакторе кода VSCode или в базе знаний Obsidian, CSV — в Excel.
Если CSV отображается неверно, импортируйте его как UTF-8. Консоль показывает короткий итог и пути, подробности находятся в журнале.

**При незавершённом запуске** папка `технические данные` остаётся **неупакованной**, чтобы сохранить checkpoint. Не удаляйте её. Для продолжения обхода добавьте `--resume` и путь к checkpoint из журнала:

| Windows | macOS |
|---|---|
| `.\start.bat -preview sk --resume "C:\путь\к\checkpoint"` | `python3 start.py -preview sk --resume "/путь/к/checkpoint"` |

Вводите прежние реестр, папку и корень. Здесь нужен каталог checkpoint, не ZIP. Для обычного нового запуска `--resume` не нужен.

При желании задайте базовую папку отчётов (по дефолту используется `Downloads`) в начале `account.toml`, **до любых секций `[auth]` и других**:

```toml
# Windows — пример; выберите свою отдельную папку
results_dir = 'C:\SarexResults'

# Для macOS вместо строки выше:
results_dir = '/Users/incognito/SarexResults'
```

Оставьте только одну строку `results_dir`. Каталог программа создаст сама.
Отчёты нельзя размещать внутри папок исходных Excel/PDF.

## 7. Тестовая загрузка в 99-Тест

Это работа с Sarex.

| Действие | Windows | macOS |
|---|---|---|
| Подготовить синтетический PDF и проверить цель, без отправки | `.\start.bat -test-pdf` | `python3 start.py -test-pdf` |
| Отправить подготовленный PDF | `.\start.bat -test-pdf --send ХЕШ_ПЛАНА` | `python3 start.py -test-pdf --send ХЕШ_ПЛАНА` |

Первая команда использует сохранённую учётную запись, читает метаданные и создаёт локальные синтетические PDF/Excel. Пути к клиентским файлам не запрашиваются. Цель фиксирована: `99-Тест`, корень **2093037**, конечная папка **7915046**. Перенаправить тест в 00-ТехЗак нельзя.

После первой команды, во второй команде замените `ХЕШ_ПЛАНА` полным SHA-256-хэшем из **вывода первой команды** (длинный набор символов - будет в последней строке вывода в консоли). Дополнительно ответьте `да` на вопрос об отправке. Проверяется не более одного закреплённого PDF. Успешный результат содержит ID и URL, ссылка сохраняется в новую тестовую книгу `registry.test.xlsx`.

Повтор той же команды с тем же хешем и сохранённым журналом должен проверить уже созданный документ без повторной загрузки. Не удаляйте состояние для получения нового теста. Неопределённый результат POST запрещает повтор.

Состояние теста:
Windows `%USERPROFILE%\.sarex-loader-synthetic-test`,
macOS `~/.sarex-loader-synthetic-test`.
Внутри:
- `input` — синтетические файлы,
- `manifest.json` — план,
- `journal` — SQLite,
- `result-*` — отчёты отдельных запусков.
Точный путь печатается в терминале.

## 8. Рабочая загрузка СК/ВК — после проверки теста и отчёта preview

**Эти команды могут создавать документы в 00-ТехЗак.**
Для просмотра без отправки используйте `--dry-run` из раздела 4.

| Windows | macOS |
|---|---|---|
| `.\start.bat -load sk` | `python3 start.py -load sk` |
| `.\start.bat -load vk` | `python3 start.py -load vk` |

Программа последовательно попросит:

1. Полный путь к Excel выбранного реестра.
2. Полный путь к локальной папке его PDF.
3. Ссылку на корневую папку СК или ВК в Sarex.

После проверки программа сохранит **`ПЛАН.md`** и напечатает, где он находится. Откройте его: проверьте, что каждому PDF назначены правильные офис, подрядчик и месяц. `ID` — уникальный номер папки Sarex; он помогает отличить одноимённые папки. SHA-256 — контрольный код плана, защищающий от его незаметного изменения; для обычного `-load` переписывать этот код вручную не нужно.

Вернитесь в окно программы и ответьте на вопрос об отправке: **`да`** — начать загрузку, **`нет`** — отменить. Пока вы не ответили `да`, исходные PDF, Excel и Sarex не меняются. При этом уже могут появиться локальные отчёты и служебный журнал проверки.

После `да` программа проверяет цели и дубликаты, последовательно загружает разрешённые PDF, подтверждает результат GET и записывает URL **в переданный исходный Excel** с резервной копией. Ошибочные PDF пропускаются с причинами. По умолчанию отсутствующие месячные папки не создаются, соответствующие PDF пропускаются. Включение этой функции описано ниже.

Только файлы с доказанно отсутствующим в Excel номером перемещаются в локальную подпапку **«не найдено»** выбранной папки PDF. Она создаётся автоматически при необходимости. Для запрета этих перемещений добавьте `--no-move`, например ` .\start.bat -load sk --no-move `. Это загрузит разрешенные файлы, но не загрузит и не переместит файлы в подпапку **«не найдено»**.

Рабочее состояние хранится вне папки программы:
Windows `%USERPROFILE%\.sarex-loader-production-journal`,
macOS `~/.sarex-loader-production-journal`.
Это постоянный SQLite-журнал и блокировки для обоих профилей.
**Не удаляйте, не сбрасывайте и не подменяйте его.** При созданном документе и неудачном сохранении Excel повтор восстанавливает URL без нового POST.

`Ctrl+C` во время отправки запрашивает остановку после текущего PDF и сохранения состояния. Дождитесь завершения; не закрывайте терминал принудительно. Не обрабатывайте одну партию одновременно на разных компьютерах: их локальные журналы не синхронизированы.

### Включить или выключить создание месячных папок

**По умолчанию выключено.** После настройки аккаунта командой `-setup` можно изменить настройку без редактирования файлов:

| Действие | Windows | macOS |
|---|---|---|
| Узнать текущую настройку | `.\start.bat -folders status` | `python3 start.py -folders status` |
| Разрешить создание | `.\start.bat -folders on` | `python3 start.py -folders on` |
| Запретить создание | `.\start.bat -folders off` | `python3 start.py -folders off` |

Эти команды **сами ничего не создают в Sarex**. Они сохраняют настройку для следующих запусков. Повторный `-setup` снова выключает создание папок.

При включённой настройке создания папок рабочий `-load sk/vk` сначала обрабатывает документы для существующих папок. Затем показывает полные пути недостающих месяцев и отдельно спрашивает: **«Создать отсутствующие папки? (да/нет)»**. Только ответ `да` разрешает попытку создания. Нужны соответствующие права аккаунта Sarex.

Создаются только месячные папки внутри однозначно найденных родителей, с принятым в этой ветке названием. Программа не создаёт офисы или подрядчиков. При неоднозначном имени, неполученных метаданных или конфликте папка пропускается. После успешного создания папок **произведите загрузку PDF той же командой**: в текущем запуске PDF в новые папки не отправляются, тк создаются папки. Результаты создания будут в `ПАПКИ.md` рядом с остальными отчётами.

`-preview`, `-load … --dry-run`, `-fill` и `-test-pdf` не создают папки даже при `on`. Состояние создания хранится в `.sarex-loader-folder-journal` в папке пользователя; не удаляйте его. При неопределённом результате операция блокируется до сверки, без повторной попытки создания.

**Ограничение:** создание папок проверено автоматическими тестами с имитацией API, а не реальной операцией на сервере. Реальное создание в Sarex требует дополнительных прав на создание папок, которыми аккаунт не обладал. **Рекомендуется** найти файл, запись которого имеется в эксель и для которого нет необходимой папки месяца в инспекциях, перенести его в отдельную новую папку, и только на одном файле проверить загрузку с добавлением папок.

## 9. Состав папки и обновление

Минимальная поставка содержит:

```text
sarex-loader-v0.1.0-rc.8-<платформа>/
├── README.md                  ← эта инструкция
├── start.bat                  ← только Windows
├── start.command              ← только macOS, дополнительный ярлык
├── start.py                   ← общий запуск и автоматическая установка
├── account.toml               ← пустой при поставке; ваш аккаунт после -setup
├── customer.routes.toml       ← служебная конфигурация поставки
├── pyproject.toml             ← версия и зависимости Python
├── MANIFEST.in                ← состав устанавливаемого пакета
├── src/sarex_loader/           ← код, внутренние правила маршрутов и ресурсы
└── tools/mock_demo.py          ← безопасная офлайн-проверка
```

Не удаляйте файлы внутри `src`: там находятся проверки безопасности и общие компоненты. Файл `profile-routes.toml` внутри пакета содержит рабочие правила; самостоятельное изменение `customer.routes.toml` не меняет маршрутизацию коротких команд.

После первого запуска дополнительно появляются `.venv` и иногда служебные `build`, `*.egg-info`, `__pycache__` — результаты установки Python. Их нет в исходном ZIP. Ничего переносить из них на другую ОС не нужно. SQLite-состояние и отчёты находятся в местах, описанных выше.

При обновлении распакуйте новую версию **в отдельную папку**, выполните `-help`, офлайн-тест и `-setup`. Не копируйте старую `.venv` и не удаляйте журналы из профиля пользователя. После обновления повторите preview. Для передачи другому человеку используйте исходный клиентский ZIP с пустым аккаунтом, а не свою уже настроенную папку.

## 10. Если что-то не получилось

| Ситуация | Что сделать |
|---|---|
| `start.bat` / `start.py` не найден | Открыть терминал в папке с этими файлами, а не на уровень выше и не внутри ZIP |
| Python не найден / слишком старый | Установить Python по разделу 1, открыть новый терминал; на Windows проверить `py -3 --version` |
| Ошибка установки зависимостей | Проверить интернет и право записи в папку программы; повторить `-help`. Не устанавливать в Program Files |
| Ошибка HTTPS на macOS | Для Python с python.org выполнить Install Certificates.command; не отключать TLS |
| Не удалось сохранить Excel | Закрыть книгу и проверить права; сохранить отчёт, резервную копию и журнал |
| Папка не найдена | Проверить путь в отчёте. Отсутствующую папку создаёт уполномоченный пользователь Sarex, затем повторяется preview |
| Дата PDF не совпадает с Excel | Маршрут показан по Excel, загрузка блокируется. Исправление клиентских данных автоматически не выполняется |
| Несколько совпадений / дубликаты | Документ пропускается; проверить строки Excel и реальные документы, не выбирать произвольный вариант |
| `OUTCOME_UNKNOWN` | Не повторять отправку и не удалять журнал; передать диагностику мне |
| Где посмотреть ошибки? | Сначала ИТОГИ.md, затем подробный отчёт/CSV, после — журнал.txt |
| Как проверить без изменения Sarex? | Офлайн-тест без аккаунта; с аккаунтом — preview/dry-run; fill не меняет Sarex, но изменяет указанный Excel |

Завершённый обход Gateway принят как достаточный источник. Конкретные ошибки GET, непроверенные ветки, признаки обрезанной выдачи, конфликтующие номера/даты и неоднозначные назначения остаются причинами пропуска заполнения.

Сценарии приёмки с командами и ожидаемыми результатами: [ACCEPTANCE.md](https://github.com/alesulkins/sarex-loader/blob/main/ACCEPTANCE.md).

## 11. Ограничения и обязательная проверка перед использованием

**Объём партии:** не запускайте сразу папку с тысячами PDF, например 10 000–20 000. Такой объём не прошёл приёмку текущей поставки. Сначала проверьте сценарии по одному PDF, затем используйте отдельные рабочие папки по **10–20 PDF**, каждый раз выполняя preview/dry-run и проверяя итоговый отчёт. Это рекомендация для осторожного начала, а не гарантированный лимит или обещание успешной загрузки каждого файла. Точное число, которое «обязательно пройдёт», не установлено: результат зависит от данных, маршрутов, прав, сети и Sarex. Увеличивать партии можно только после успешной проверки заказчиком. Уменьшение числа PDF не сокращает рекурсивный обход выбранного корня Sarex; обработка может занять время. Не запускайте одну партию одновременно в нескольких процессах или на разных компьютерах.

Программа передаётся для самостоятельной проверки и эксплуатации заказчиком. **Перед первой рабочей загрузкой, а также после обновления программы, изменения реестров или структуры Sarex заказчик обязан:**

1. Выполнить `-preview sk` / `-preview vk` для используемых реестров.
2. Выполнить `-load sk --dry-run` / `-load vk --dry-run`.
3. Открыть `ИТОГИ.md`, подробный отчёт и CSV. Проверить, **какой PDF в какую папку предполагается загрузить**: реестр, офис, подрядчик, месяц, полный путь и ID. Проверить причины пропусков и план перемещения в «не найдено».
4. Перед рабочим `-load` прочитать `ПЛАН.md`. Если назначение неверно или непонятно — ответить `нет`, сохранить отчёт и уточнить правила. Не подтверждать план только потому, что программа не показала ошибку.
5. Сохранить резервные копии исходных Excel/PDF. Для проверки `-fill` сначала использовать копию Excel: эта команда записывает ссылки без отдельного подтверждения.

**Ограничения:** preview и dry-run показывают предполагаемый результат по данным на момент проверки, а не гарантируют будущий результат отправки, так как между проверкой и загрузкой данные, права доступа и структура Sarex могут измениться. Программа не исправляет клиентские данные и не выбирает произвольный вариант при неоднозначности. Неподтверждённые маршруты, конфликты дат, дубликаты и ошибки API приводят к пропуску. Реальное создание папок месяцев в этом выпуске ещё не прошло отдельную приёмку на сервере; по умолчанию оно выключено.

После передачи программы заказчик самостоятельно отвечает за проверку исходных данных и отчётов, выбор учётной записи и каталогов, подтверждение загрузки или создания папок, сохранность резервных копий и дальнейшую эксплуатацию. Автор не контролирует действия пользователей после передачи и не принимает на себя ответственность за последствия запуска без предусмотренных проверок, подтверждения неверных назначений, самостоятельного изменения программы или правил, удаления журналов и использования некорректных исходных данных.
