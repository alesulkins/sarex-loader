# Sarex Loader

Загрузка инспекционных PDF в нужные папки Sarex по Excel-реестру и восстановление пустых ссылок `URL` в Excel. СК и ВК обрабатываются **раздельно**. Перед загрузкой можно проверить места назначения файлов и папок без изменения файловой структуры Sarex.

Программа работает в терминале. Нужны **Python 3.11 и выше**, интернет и учётная запись в Sarex.
Для новой установки Python используйте обычную сборку Python 3.13/3.14.

# 1. Установка

## 1.1. Windows

**Python**

1. Для Intel/AMD скачайте **Windows installer (64-bit)** [версии 3.14](https://www.python.org/ftp/python/3.14.10/python-3.14.10-amd64.exe).
2. В установщике отметьте **Add python.exe to PATH**, затем **Install Now**. Закройте и заново откройте PowerShell.

**Либо** если удобнее скачать установщик командой (ничего заменять не нужно: `$env:USERPROFILE` автоматически обозначает вашу папку пользователя):

```powershell
$installer = Join-Path $env:USERPROFILE "Downloads\python-3.14.10-amd64.exe"
Invoke-WebRequest "https://www.python.org/ftp/python/3.14.10/python-3.14.10-amd64.exe" -OutFile $installer
Start-Process -FilePath $installer -Wait
```

Проверьте в новом PowerShell:

```powershell
python --version
```

## 1.2. Sarex loader&fill

1. Скачайте [Windows ZIP](https://github.com/alesulkins/sarex-loader/releases/download/v0.1.0-rc.9/sarex-loader-v0.1.0-rc.9-windows.zip) в «Загрузки».
2. Нажмите правой кнопкой → **Извлечь всё**.
3. Перенесите распакованную папку в «Документы», например в `Documents\SarexLoader`.

Можно распаковать командой в другую папку (ничего заменять не нужно: `$env:USERPROFILE` автоматически обозначает вашу папку пользователя):

```powershell
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\sarex-loader-v0.1.0-rc.9-windows.zip" -DestinationPath "$env:USERPROFILE\Documents\SarexLoader-rc9"
Set-Location "$env:USERPROFILE\Documents\SarexLoader-rc9\sarex-loader-v0.1.0-rc.9-windows"
.\start.bat -help
```

При ручной распаковке найдите **папку `sarex-loader-v0.1.0-rc.9-windows`**. 
Нужна именно эта папка, а не ZIP и не внешняя папка, в которую его распаковали.

Нажмите **Win+R**, введите `powershell` и нажмите Enter — откроется окно для ввода команд. Введите `cd "полный путь к папке sarex-loader-v0.1.0-rc.9-windows"`, заменив текст в кавычках своим путём. Например, если перенесли папку в «Документы»:

```powershell
cd "$env:USERPROFILE\Documents\sarex-loader-v0.1.0-rc.9-windows"
.\start.bat -help
```

Здесь заменять путь нужно **только если вы сохранили программу в другом месте**. Все следующие команды запускайте в этом окне.

Первый запуск создаёт `.venv` и скачивает зависимости.
Нужен интернет; дождитесь справки.
**Активировать `.venv` и менять ExecutionPolicy не нужно.**
При проблеме с BAT можно запустить `py -3 start.py -help`.
Для меню — дважды нажать `start.bat` или выполнить ` .\start.bat ` без аргументов.

**Создание папок: `-folders on` и `-folders off`**

- `.\start.bat -folders on` — включить возможность создания отсутствующих папок месяцев. Тогда при `-load [sk/vk]` программа сначала обработает PDF для существующих папок, затем покажет список необходимых месяцев и отдельно спросит разрешение на создание. После создания повторите `-load [sk/vk]`, чтобы загрузить оставшиеся PDF.
- `.\start.bat -folders off` — запретить создание папок. PDF для существующих папок загружаются как обычно; файлы, которым не хватает месяца, пропускаются с объяснением в отчёте.
- `.\start.bat -folders status` — посмотреть текущую настройку.

**Когда использовать:** 
если разрешена загрузка только в существующие папки — выбирайте `off`. Если разрешено дополнительно создавать необходимые месяцы — выбирайте `on`.

Настройка сохраняется между запусками. 
Если оставить `on`, существующие папки повторно не создаются, а новые требуют отдельного подтверждения "да" для создания. 
Если оставить `off`, отсутствующие месяцы просто не будут созданы. 
Режим сохраняется до первого переключения режима (с `on`на `off` или с `off` на `on`), поэтому если загружаете файлы, то имейте в виду, что предыдущая конфигурация осталась с прошлого изменения режима => надо проверять статус флага создания папок или не писать "да" бездумно для создания папок. 

**Важно:** `off` запрещает только создание папок, но не загрузку PDF! Команда `-load` без `--dry-run` записывает документы в Sarex после подтверждения плана при любой настройке. Для проверки без изменений используйте `-preview` или `-load … --dry-run` — они ничего не создают и не загружают даже при `on`.

Программа создаёт только папки месяцев внутри подтверждённого родителя. Папки офисов и подрядчиков не создаются. Перед подтверждением создания обязательно проверяйте полные пути.

## 2. Проверка без учётной записи и без Sarex

Все команды ниже выполняйте **из распакованной папки своей ОС**: `sarex-loader-v0.1.0-rc.9-windows`.

Сначала `-help`, затем офлайн-тест:

| Действие | Windows PowerShell | macOS |
|---|---|---|
| Справка | `.\start.bat -help` | `python3 start.py -help` |
| Офлайн-тест | `.\.venv\Scripts\python.exe tools\mock_demo.py test-offline-1` | `.venv/bin/python tools/mock_demo.py test-offline-01` |

Офлайн-тест **не подключается к Sarex**, не требует аккаунта и сам создаёт синтетические PDF, Excel и отдельный SQLite.
Ожидаемый результат: **1 новый синтетический документ, 2 дубликата пропущены, повторных отправок 0**.
Это имитация, а не реальная загрузка.

При повторной независимой проверке укажите новое имя, например `test-offline-2`. Программа сама создаст эту тестовую папку рядом с собой. Имя должно быть новым, чтобы не перезаписать прошлые результаты. Указывайте простое имя, например `test-offline-02`, без слешей и без `..` (обозначение перехода в родительскую папку).

## 4. Подготовьте данные и проверьте назначения

- `.xlsx` со столбцами `ID`, `Дата`, `П_Офис`, `Подрядчик`, `Номер`, `URL`. Закройте книгу в Excel!
- СК и ВК — отдельные папки PDF. Обрабатываются PDF **непосредственно в выбранной папке**, без обхода подпапок. Для второй папки PDF сделайте отдельный запуск.
- В OneDrive выберите «Всегда хранить на этом устройстве» и дождитесь скачивания. Требуется локальный путь, веб-ссылка на OneDrive не подходит.
- Храните Excel и PDF отдельно от программы и отчётов. Например, программа — `Documents\SarexLoader`, данные — `Documents\SarexData`, отчёты — по умолчанию `Downloads` (можно поменять расположение в конфиге. хотя, на мой взгляд, это самый удобный вариант расположения, так как хранить отчеты нет необходимости - после проверки работы команды папку можно удалить).
- В Windows скопируйте путь до файла через «Копировать как путь».

## 5. Проверка путей назначения файлов

| Режим | Windows | macOS |
|---|---|---|
| Проверить СК без отправки в СОД| `.\start.bat -preview sk` | `python3 start.py -preview sk` |
| Проверить ВК без отправки в СОД| `.\start.bat -preview vk` | `python3 start.py -preview vk` |
| Проверить загрузку СК без отправки в СОД| `.\start.bat -load sk --dry-run` | `python3 start.py -load sk --dry-run` |
| Проверить загрузку ВК без отправки в СОД| `.\start.bat -load vk --dry-run` | `python3 start.py -load vk --dry-run` |

`.\start.bat -preview sk` и `.\start.bat -load sk --dry-run` - аналогичные команды. Первая просто проще. 
- **`-preview sk`** — сопоставляет PDF СК с Excel СК, проверяет папки и документы Sarex и показывает, что можно загрузить и что будет пропущено.
- **`-load sk --dry-run`** — безопасный проверочный запуск команды загрузки СК. Сейчас выполняет ту же проверку, что `-preview sk`, без отправки файлов.

Все четыре команды создают только локальные отчёты. PDF, Excel и Sarex остаются без изменений.

| 2 | Локальная папка PDF | Путь к папке СК или ВК на этом компьютере |

Папка отчётов создаётся автоматически. Программа читает структуру выбранного корня, проверяет Excel/PDF и формирует отчёт.
Если номера PDF нет в Excel, отчёт покажет: при рабочей загрузке этот файл попадёт в локальную подпапку «не найдено». 
Во время проверки файл остаётся на месте. Проверка использует настоящие данные Excel/PDF и структуру Sarex, но не отправляет документы.

| Windows | macOS |

## 7. Где находятся результаты

После preview/dry-run, fill или load откройте путь, напечатанный в терминале.
По умолчанию это папка `Downloads/отчет-ГГГГ-ММ-ДД-ЧЧ-ММ-СС`.

```text
отчет-2026-11-05-18-30-00/
├── ИТОГИ.md                   ← открыть первым: статистика и ссылки
├── PDF_UPLOAD_PREVIEW.md      ← для проверки PDF: назначения и причины
├── pdf_upload_preview.csv     ← подробная таблица PDF
├── …другие отчёты режима      ← для fill: результаты поиска URL по строкам
├── журнал.txt                 ← подробный ход работы и ошибки
├── технические-данные.zip     ← снимок дерева, планы, checkpoint, диагностика
└── резервные копии Excel/     ← при сохранении Excel; не прячутся в ZIP
```

Набор подробных отчётов зависит от команды.
Markdown можно читать в Блокноте/TextEdit, но удобнее всего в редакторе кода VSCode или в базе знаний Obsidian, CSV — в Excel.
Если CSV отображается неверно, импортируйте его как UTF-8. Консоль показывает короткий итог и пути, подробности находятся в журнале.

**При незавершённом запуске** папка `технические данные` остаётся **неупакованной**, чтобы сохранить checkpoint. Не удаляйте её до полного завершения программы. Для продолжения обхода добавьте `--resume` и путь к checkpoint из журнала:

| Windows | macOS |
|---|---|
| `.\start.bat -preview sk --resume "C:\путь\к\checkpoint"` | `python3 start.py -preview sk --resume "/путь/к/checkpoint"` |

Вводите прежние реестр, папку и корень. Здесь нужен каталог checkpoint, не ZIP. Для обычного нового запуска `--resume` не нужен.

При желании задайте базовую папку отчётов (по дефолту используется `Downloads`) в начале `account.toml`, **до любых секций `[auth]` и других**:

```toml
# Windows — пример; выберите свою отдельную папку
results_dir = 'C:\SarexResults'

# Для macOS вместо строки выше:
results_dir = '/Users/incognito/SarexResults'
```

Оставьте только одну строку `results_dir`. Каталог программа создаст сама.
Отчёты нельзя размещать внутри папок исходных Excel/PDF.

## 8. Тестовая загрузка в 99-Тест

| Действие | Windows | macOS |
|---|---|---|
| Подготовить синтетический PDF и проверить цель, без отправки | `.\start.bat -test-pdf` | `python3 start.py -test-pdf` |
| Отправить подготовленный PDF | `.\start.bat -test-pdf --send ХЕШ_ПЛАНА` | `python3 start.py -test-pdf --send ХЕШ_ПЛАНА` |

Первая команда использует сохранённую учётную запись, читает метаданные и создаёт локальные синтетические PDF/Excel. Пути к клиентским файлам не запрашиваются. Цель фиксирована: `99-Тест`, корень **2093037**, конечная папка **7915046**. Перенаправить тест в 00-ТехЗак нельзя.

После первой команды, во второй команде замените `ХЕШ_ПЛАНА` полным SHA-256-хэшем из **вывода первой команды** (длинный набор символов - будет в последней строке вывода в консоли). Дополнительно ответьте `да` на вопрос об отправке. Проверяется не более одного закреплённого PDF. Успешный результат содержит ID и URL, ссылка сохраняется в новую тестовую книгу `registry.test.xlsx`.

Повтор той же команды с тем же хешем и сохранённым журналом должен проверить уже созданный документ без повторной загрузки. Не удаляйте состояние для получения нового теста. 

Состояние теста:
Windows `%USERPROFILE%\.sarex-loader-synthetic-test`,

Внутри:
- `input` — синтетические файлы,
- `manifest.json` — план,
- `journal` — SQLite,
- `result-*` — отчёты отдельных запусков.
Точный путь печатается в терминале.

## 9. Рабочая загрузка СК/ВК — после проверки теста и отчёта preview

**Эти команды могут создавать документы в 00-ТехЗак.**
Для просмотра без отправки используйте `--dry-run` из раздела 4.

| Windows | macOS |
|---|---|---|
| `.\start.bat -load sk` | `python3 start.py -load sk` |
| `.\start.bat -load vk` | `python3 start.py -load vk` |

Программа последовательно попросит 3 вопроса:

| № | Вопрос | Пример ответа |
|---|---|---|
| 1 | Полный путь к Excel соответствующего реестра | Windows: `C:\Users\incognito\Documents\SarexData\Инспекции СК.xlsx` |
| 2 | Локальная папка PDF | Путь к папке СК или ВК на этом компьютере |
| 3 | Ссылка на корень Sarex | СК: `https://lk.sarex.io/documentations/2066367`; ВК: `http

После проверки программа сохранит **`ПЛАН.md`** и напечатает, где он находится. Откройте его: проверьте, что каждому PDF назначены правильные офис, подрядчик и месяц. `ID` — уникальный номер папки Sarex; он помогает отличить одноимённые папки. SHA-256 — контрольный код плана, защищающий от его незаметного изменения; для обычного `-load` переписывать этот код вручную не нужно.

Вернитесь в окно программы и ответьте на вопрос об отправке: **`да`** — начать загрузку, **`нет`** — отменить. Пока вы не ответили `да`, исходные PDF, Excel и Sarex не меняются. При этом уже могут появиться локальные отчёты и служебный журнал проверки.

После `да` программа проверяет цели и дубликаты, последовательно загружает разрешённые PDF, подтверждает результат GET и записывает URL **в переданный исходный Excel** с резервной копией. Ошибочные PDF пропускаются с причинами. По умолчанию отсутствующие месячные папки не создаются, соответствующие PDF пропускаются. Включение этой функции описано ниже.

Только файлы с доказанно отсутствующим в Excel номером перемещаются в локальную подпапку **«не найдено»** выбранной папки PDF. Она создаётся автоматически при необходимости. Для запрета этих перемещений добавьте `--no-move`, например ` .\start.bat -load sk --no-move `. Это загрузит разрешенные файлы, но не загрузит и не переместит файлы в подпапку **«не найдено»**.

Рабочее состояние хранится вне папки программы:
Windows `%USERPROFILE%\.sarex-loader-production-journal`,
Это постоянный SQLite-журнал и блокировки для обоих профилей.

Журнал сохраняйте между запусками и обновлениями программы. Не удаляйте и не заменяйте его самостоятельно: это может привести к потере истории операций и риску повторной загрузки. Если журнал повреждён, требуется перенос на другой компьютер или очистка — сначала сохраните резервную копию и обратитесь к разработчику.

`Ctrl+C` во время отправки запрашивает остановку после текущего PDF и сохранения состояния. Дождитесь завершения; не закрывайте терминал принудительно. Не обрабатывайте одну партию одновременно на разных компьютерах: их локальные журналы не синхронизированы.

### Включить или выключить создание папок месяцев

**По умолчанию выключено.** 

| Действие | Windows | macOS |
|---|---|---|
| Узнать текущую настройку | `.\start.bat -folders status` | `python3 start.py -folders status` |
| Разрешить создание | `.\start.bat -folders on` | `python3 start.py -folders on` |
| Запретить создание | `.\start.bat -folders off` | `python3 start.py -folders off` |

Эти команды **сами ничего не создают в Sarex**. Они сохраняют настройку для следующих запусков. Повторный `-setup` снова выключает создание папок.

При включённой настройке создания папок рабочий `-load sk/vk` сначала обрабатывает документы для существующих папок. Затем показывает полные пути недостающих месяцев и отдельно спрашивает: **«Создать отсутствующие папки? (да/нет)»**. Только ответ `да` разрешает попытку создания. Нужны соответствующие права аккаунта Sarex.

Создаются только папки месяцев внутри однозначно найденных родителей, с принятым в этой ветке названием. Программа не создаёт офисы или подрядчиков. При неоднозначном имени, неполученных метаданных или конфликте папка пропускается. **Для PDF, у которого отсутствует папка месяца, нужны два запуска:** первый создаёт только папку месяца после подтверждения; затем повторно запустите `-load sk` или `-load vk` с теми же входными данными — PDF будет загружен, если все проверки пройдут. В новые папки PDF в первом запуске не отправляются. Другие корректные PDF, чьи папки уже существуют, могут загрузиться в первом запуске. Результаты создания будут в `ПАПКИ.md` рядом с остальными отчётами.

`-preview`, `-load … --dry-run`, `-fill` и `-test-pdf` не создают папки даже при `on`. Состояние создания хранится в `.sarex-loader-folder-journal` в папке пользователя; не удаляйте его. При неопределённом результате операция блокируется до сверки, без повторной попытки создания.

**Ограничение:** создание папок проверено автоматическими тестами с имитацией API, а не реальной операцией на сервере. Реальное создание в Sarex требует дополнительных прав на создание папок, которыми аккаунт не обладал. **Рекомендуется** найти файл, запись которого имеется в эксель и для которого нет необходимой папки месяца в инспекциях, перенести его в отдельную новую папку, и только на одном файле проверить загрузку с добавлением папок.

Для передачи другому человеку используйте исходный клиентский ZIP с пустым аккаунтом, либо ссылку на этот репозиторий, а не свою уже настроенную папку.

## 12. Ограничения и обязательная проверка перед использованием

**Объём партии:** не запускайте сразу папку с тысячами PDF, например 10 000–20 000. Сначала проверьте сценарии по одному PDF, затем используйте отдельные рабочие папки по **100-500 PDF** и так далее повышая объем выборки, каждый раз выполняя preview/dry-run и проверяя итоговый отчёт. Это рекомендация. Точное число файлов, которое «обязательно пройдёт», не установлено, так как результат зависит от данных, объема, маршрутов, прав, сети и Sarex. Уменьшение числа PDF не сокращает рекурсивный обход выбранного корня Sarex; обработка может занять время. Не запускайте одну партию одновременно в нескольких процессах или на разных компьютерах из-за возможной проблемы синхронизации и гонок данных.

Программа передаётся для самостоятельной проверки и эксплуатации заказчиком. **Перед первой рабочей загрузкой, а также после обновления программы, изменения реестров или структуры Sarex заказчик обязан:**

1. Выполнить `-preview sk` / `-preview vk` для используемых реестров.
2. Выполнить `-load sk --dry-run` / `-load vk --dry-run`.
3. Открыть `ИТОГИ.md`, подробный отчёт и CSV. Проверить, **какой PDF в какую папку предполагается загрузить**: реестр, офис, подрядчик, месяц, полный путь и ID. Проверить причины пропусков и план перемещения в «не найдено».
4. Перед рабочим `-load` прочитать `ПЛАН.md`. Если назначение неверно или непонятно — ответить `нет`, сохранить отчёт и уточнить правила. Не подтверждать план только потому, что программа не показала ошибку.
5. Сохранить резервные копии исходных Excel/PDF. Для проверки `-fill` сначала использовать копию Excel: эта команда записывает ссылки без отдельного подтверждения.

**Ограничения:** preview и dry-run показывают предполагаемый результат по данным на момент проверки, а не гарантируют будущий результат отправки, так как между проверкой и загрузкой данные, права доступа и структура Sarex могут измениться. Программа не исправляет клиентские данные и не выбирает произвольный вариант при неоднозначности. Неподтверждённые маршруты, конфликты дат, дубликаты и ошибки API приводят к пропуску. Реальное создание папок месяцев в этом выпуске ещё не прошло отдельную проверку на сервере; по умолчанию оно выключено.
