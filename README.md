# Sarex Loader

Проверка инспекционных PDF и восстановление ссылок в Excel. Один запуск обрабатывает **только СК (`sk`) или только ВК (`vk`)**.

**Статус текущей версии:** просмотр и восстановление URL доступны. Загрузка в рабочие разделы `00-ТехЗак` и создание папок выключены. Тестовая отправка в `99-Тест` доступна на macOS/Linux; на Windows пока заблокирована. Инструкция ниже отделяет доступные команды от ещё не подключённых.

## 1. Windows: установка и открытие программы

1. Установите Python **3.11 или новее** с [python.org](https://www.python.org/downloads/windows/). При установке включите **Add Python to PATH**. Затем заново откройте терминал.
2. Распакуйте клиентский архив `…-windows.zip`, например в `C:\SarexLoader`. Не запускайте программу внутри ZIP. Используйте подготовленный клиентский архив, а не GitHub **Source code**.
3. Откройте распакованную папку в Проводнике, нажмите адресную строку, введите `powershell` и нажмите Enter. Терминал откроется в нужной папке.
4. Введите:

```powershell
.\start.bat -help
```

Первый запуск создаст `.venv` и установит зависимости — нужен интернет. Дождитесь справки. Последующие запуски используют установленное окружение. Активировать `.venv`, менять политику PowerShell и редактировать Python-код не нужно.

Все Windows-команды ниже запускаются **в этой же папке**. Если `start.bat` не найден, перейдите в папку программы:

```powershell
cd "C:\SarexLoader"
```

Замените пример своим расположением. Альтернативный запуск, если установлен Python Launcher: `py start.py -help`.

## 2. Учётная запись — один раз

```powershell
.\start.bat -setup
```

Программа спросит по порядку:

| Запрос | Что вводить |
|---|---|
| `Логин Sarex:` | Ваш логин Sarex, обычно адрес электронной почты |
| `Пароль Sarex (скрытый ввод):` | Пароль, затем Enter. Символы и звёздочки не отображаются — это нормально |

Настройки сохраняются в `account.toml` рядом с программой. Повторять ввод при каждом запуске не нужно. Для смены аккаунта снова выполните `-setup`. Если начать с `-preview` или `-fill` без настроек, программа сначала предложит ввести учётную запись. `-help` авторизацию не требует.

Клиентский архив содержит пустой образец авторизации. Не передавайте заполненный `account.toml` посторонним и не публикуйте его. Создание папок остаётся отключённым: `allow_folder_creation = false`.

## 3. Подготовьте Excel и PDF

- Нужен настоящий Excel-реестр, например `Инспекции СК.xlsx`. **Не выбирайте файл, начинающийся с `~$`**: это служебный файл открытого Excel.
- СК и ВК должны лежать в отдельных папках. PDF проверяются только непосредственно в выбранной папке; вложенные папки не обходятся. Для нескольких папок СК выполняйте отдельный запуск для каждой.
- Для OneDrive используйте локальную синхронизированную папку с полностью скачанными файлами. Облачного ярлыка недостаточно для отправки PDF. Ссылка на веб-страницу OneDrive вместо локального пути не подходит.
- Закройте Excel перед восстановлением ссылок. Для первой проверки сделайте отдельную копию книги.
- Рекомендуемое размещение: `C:\SarexData\Excel\…` и `C:\SarexData\PDF\СК` / `ВК`. Отчёты должны находиться отдельно от исходных папок.

Путь можно скопировать из адресной строки Проводника; для файла — через «Копировать как путь». Вводите полный путь, без обратного слеша после имени Excel. В примерах ниже заменяйте пути своими.

## 4. Сначала безопасная проверка СК и ВК

Выполняйте команды по одной:

```powershell
.\start.bat -preview sk
.\start.bat -preview vk
```

Каждая команда спросит **три значения по порядку**:

| Порядок | Для СК (`sk`) | Для ВК (`vk`) |
|---|---|---|
| 1. Полный путь к Excel | `C:\SarexData\Excel\Инспекции СК.xlsx` | `C:\SarexData\Excel\Инспекции ВК.xlsx` |
| 2. Локальная папка PDF | `C:\SarexData\PDF\СК` | `C:\SarexData\PDF\ВК` |
| 3. Ссылка на корень Sarex | `https://lk.sarex.io/documentations/2066367` | `https://lk.sarex.io/documentations/2067117` |

После каждого значения нажимайте Enter. Не вводите `sk/vk` буквально: выбирайте один профиль. Для этих команд не подставляйте ссылку на `99-Тест` или отдельную месячную папку.

Программа читает дерево выбранного корня, сопоставляет PDF с Excel и создаёт отчёты. **Не загружает PDF, не создаёт папок в Sarex, не меняет Excel и не перемещает исходные PDF.** Обход большого раздела может занять время.

Та же безопасная проверка через команду загрузки:

```powershell
.\start.bat -load sk --dry-run
.\start.bat -load vk --dry-run
```

Вопросы и результат такие же, как у `-preview`. Это расчёт назначений по реальным данным, а не имитация успешного POST. Оставьте `--dry-run`, если нужна проверка без записи в `00-ТехЗак`.

## 5. Проверьте восстановление URL на копии Excel

Сначала самостоятельно скопируйте реестр, например в `C:\SarexData\Проверка\СК-копия.xlsx`. Затем:

```powershell
.\start.bat -fill sk
.\start.bat -fill vk
```

Программа спросит **два значения по порядку**:

1. Полный путь к Excel соответствующего профиля — для проверки укажите **копию**.
2. Ссылку на корень СК или ВК из таблицы выше.

PDF и папка PDF не требуются. В Sarex выполняется только чтение. Найденные однозначные ссылки записываются **в тот Excel, путь к которому вы ввели**. Уже заполненные URL сохраняются. Перед записью создаётся резервная копия; сохранение выполняется через временный файл с проверкой результата.

После запуска откройте отчёт и книгу: проверьте новые ссылки, неизменность остальных данных и наличие резервной копии. Повтор с той же книгой не должен заменять заполненные URL. Для работы с оригиналом впоследствии укажите путь к оригиналу — отдельный итоговый Excel вместо него не создаётся.

## 6. Тестовая загрузка в 99-Тест

**На Windows этот этап пока недоступен, включая подготовку `-test-pdf`.** Команды приведены для понимания интерфейса; текущая версия вернёт сообщение о блокировке, не запросит файлы и ничего не отправит. До завершения переноса upload используйте на Windows этапы 1–5.

Предусмотренные команды Windows:

```powershell
.\start.bat -test-pdf
.\start.bat -test-pdf --send ХЕШ_ПЛАНА
```

Сейчас тот же тест можно выполнить на macOS/Linux, отдельно разрешая реальную отправку:

```sh
python3 start.py -test-pdf
python3 start.py -test-pdf --send ХЕШ_ПЛАНА
```

Порядок работающего теста на macOS/Linux:

1. Первая команда использует сохранённую учётную запись и проверяет тестовую цель через GET. **Ничего не отправляет.** PDF и Excel создаются автоматически; ваши файлы и пути вводить не нужно.
2. В выводе проверьте имя PDF, цель и `План SHA-256`. Цель фиксирована: корень `99-Тест` — `2093037`, конечная папка — `7915046`. Другую цель выбрать нельзя.
3. Замените `ХЕШ_ПЛАНА` во второй команде полным хешем из своего вывода. Это не пароль. Не используйте хеш из чужого примера.
4. На вопрос `Разрешить отправку этого тестового PDF? Введите «да»:` введите `да`, **только если разрешаете эту реальную отправку**. Другой ответ отменяет её.
5. Программа отправляет максимум один новый синтетический PDF, проверяет документ через GET, сохраняет URL в тестовый Excel и состояние в SQLite. Папки не создаются; `00-ТехЗак` не затрагивается.
6. Проверьте полученную ссылку в браузере. Повтор той же команды использует тот же PDF и журнал: ожидается `Загружено: 0`, документ учитывается как ранее подтверждённый. Чужой совпадающий документ блокирует отправку.

Состояние теста находится в `~/.sarex-loader-synthetic-test`; точный путь результата выводится в консоль. **Не удаляйте состояние ради повторного теста.** При `OUTCOME_UNKNOWN` остановитесь: неопределённую отправку повторять нельзя. Старый `-load test` — внутренний исторический режим, для заказчика его использовать не нужно.

## 7. Реальная загрузка СК/ВК — пока не подключена

Будущие рабочие команды Windows:

```powershell
.\start.bat -load sk
.\start.bat -load vk
```

**В текущей поставке обе команды заблокированы до авторизации.** Они не спрашивают пути, не отправляют документы и не создают локальную подпапку «не найдено». Изменение `account.toml` не снимает эту блокировку. Успешный тест в `99-Тест` также не включает производственную загрузку автоматически.

Перед доступностью этого этапа нужны завершение подключения рабочего upload, нативная Windows-проверка и приёмка. Требуемое поведение после подключения: ввод Excel → папки PDF → корня выбранного профиля; отправка только проверенных файлов; GET-подтверждение; сохранение URL в переданный Excel с резервной копией. Это **описание требований, а не уже доступный сценарий**.

Подпапка **«не найдено» — локальная**, внутри выбранной папки PDF СК/ВК. При рабочей загрузке туда должны перемещаться только PDF, чей номер достоверно отсутствует в соответствующем Excel. Конфликт даты, ошибка маршрута или дубликат не означают отсутствия номера. Сейчас preview/dry-run только показывает план такого перемещения.

## Где смотреть результаты

Папку результатов вводить не нужно. Программа сама создаёт в `Downloads` вашего профиля новую папку `отчет-ГГГГ-ММ-ДД-ЧЧ-ММ-СС`. Полный путь выводится в консоль. Это правило относится к preview/dry-run и fill; у синтетического теста отдельная папка состояния, указанная выше.

Открывайте файлы в таком порядке:

1. `ИТОГИ.md` — результат запуска и пути к подробным отчётам.
2. Подробный Markdown и CSV — назначения, пропуски и причины по файлам/строкам.
3. `журнал.txt` — подробный ход обработки и ошибки.
4. `технические-данные.zip` — снимок дерева, планы и checkpoint для диагностики. Резервные копии Excel сохраняются отдельно.

Markdown можно открыть Блокнотом, CSV — в Excel. При сбое технические данные остаются неупакованными. Не удаляйте их. Для продолжения прерванного обхода укажите сохранённый checkpoint:

```powershell
.\start.bat -preview sk --resume "C:\путь\к\checkpoint"
```

Введите те же исходные пути и корень. Используйте путь именно из сообщения прерванного запуска, не имя ZIP.

Необязательно: чтобы изменить базовую папку отчётов, добавьте в начало `account.toml`, **до `[auth]`**:

```toml
results_dir = 'C:\SarexResults'
```

Папка создаётся автоматически. Используйте абсолютный локальный путь отдельно от папок Excel и PDF. Без этой настройки используется `Downloads`; повторный `-setup` сохраняет выбранное расположение.

## Если что-то не работает

| Сообщение или ситуация | Что сделать |
|---|---|
| Не найден Python | Установить Python 3.11+, включить PATH, заново открыть терминал |
| Не найден `start.bat` | Открыть терминал в распакованной папке программы |
| Ошибка чтения Excel | Проверить путь, выбрать настоящий `.xlsx`, а не `~$…`, закрыть Excel |
| PDF OneDrive недоступен | Сделать файл доступным локально и дождаться скачивания |
| Папка назначения отсутствует | Проверить полный путь в отчёте; создание папок отключено, PDF пропускается |
| Конфликт даты, номера, маршрута или несколько совпадений | Проверить данные клиента по отчёту; программа не выбирает вариант наугад |
| Ошибка GET или неполный обход | Сохранить журнал/checkpoint; затронутые операции не считаются безопасными |
| `OUTCOME_UNKNOWN` | Остановиться и передать журнал на разбор; не повторять POST, не сбрасывать SQLite |
| `-load` или тест Windows заблокирован | Это текущее ограничение реализации; использовать безопасный просмотр, не обходить блокировку |

Завершённый рекурсивный обход Gateway принят как практически достаточный источник, но абсолютная полнота API не доказана. Конкретные ошибки чтения, признаки необработанной пагинации и неоднозначности продолжают блокировать затронутые операции.

## macOS и дополнительная офлайн-проверка

Вместо `.\start.bat` используйте `python3 start.py`; аргументы и порядок вопросов те же. Пример: `python3 start.py -load sk --dry-run`.

Полная офлайн-имитация upload сейчас доступна только на macOS/Linux после первого запуска программы:

```sh
.venv/bin/python tools/mock_demo.py my-mock-test-01
```

Укажите новое имя папки результата. Используются только синтетические файлы и mock API; сеть запрещена. Проверяются новый документ, локальные дубликаты, URL и повтор без новых отправок. Это проверка механизма, а не покрытия ваших реестров.

## Windows CI, приёмка и поставка

Для разработчика: GitHub → Actions → **Windows and macOS validation** → **Run workflow** → `main`. Дождитесь обеих задач `validate` и задачи `compare`. При ошибке скачайте артефакты `validation-windows-latest` / `validation-macos-latest`: там результаты тестов и stdout/stderr запуска BAT. Нужен новый запуск на актуальном коммите, а не повтор старого задания.

CI использует только разрешённые исходники и синтетические файлы, без учётной записи Sarex, клиентских документов и исторических SQLite. Проверяет установку ZIP, CLI, Excel, файловые операции, SQLite, восстановление и равенство результатов платформ. Зелёный CI не означает, что ещё заблокированный Windows-upload уже подключён.

Порядок приёмки: [ACCEPTANCE.md](ACCEPTANCE.md). Подготовка релиза: [RELEASE_NOTES.md](RELEASE_NOTES.md) в репозитории. Финальную рабочую поставку нельзя объявлять готовой, пока этапы 6–7 недоступны на Windows и не приняты.
