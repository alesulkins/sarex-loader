# Sarex Loader

Предварительная версия для проверки маршрутизации PDF и восстановления URL в Excel СК/ВК. Один запуск работает только с одним реестром.

**Рабочая загрузка `-load sk/vk` и создание папок пока выключены.** Завершённый обход Gateway принимается как практически достаточный источник; ошибки чтения, неоднозначности, дубликаты и конфликт дат продолжают блокировать затронутые файлы. Абсолютная полнота API не доказана.

## Установка и первый запуск

1. Установите Python 3.11 или новее. На Windows включите «Add Python to PATH».
2. Распакуйте клиентский ZIP в отдельную локальную папку. Не запускайте внутри ZIP.
3. Откройте терминал в распакованной папке. На Windows используйте `py start.py`, на macOS — `python3 start.py`.
4. Первый запуск создаст `.venv` и установит зависимости: нужен интернет. Последующие запуски используют это окружение.
5. Выполните настройку авторизации один раз:

```sh
python3 start.py -setup
```

На Windows во всех командах заменяйте `python3` на `py`. Пароль вводится скрыто. Авторизация сохраняется в `account.toml` рядом с программой; этот файл следует передавать только получателю, которому разрешён доступ к аккаунту. По умолчанию клиентский ZIP содержит пустой образец. Повторный `-setup` меняет учётную запись. Пути к Excel/PDF и корню программа запрашивает при запуске; вручную редактировать Python не требуется.

Для OneDrive используйте полностью скачанную локальную папку. Закройте Excel перед сохранением ссылок.

## Команды

```sh
python3 start.py -help
python3 start.py -preview sk
python3 start.py -preview vk
python3 start.py -load sk --dry-run
python3 start.py -load vk --dry-run
python3 start.py -fill sk
python3 start.py -fill vk
```

| Команда | Sarex | Локальные файлы |
|---|---|---|
| `-preview sk/vk` | Авторизация и GET; без загрузки и создания папок | Диагностические отчёты; исходные Excel/PDF не меняет |
| `-fill sk/vk` | Авторизация и GET; не изменяет Sarex | **Заполняет пустые URL в переданном Excel**, с резервной копией и безопасным сохранением |
| `-load sk/vk --dry-run` | Только авторизация и GET; эквивалент `-preview` | Отчёты; без перемещения PDF и изменения Excel |
| `-load sk/vk` | Пока заблокирована до авторизации | Не является доступным рабочим режимом |

Подпапка «не найдено» относится к локальной папке PDF, а не к Sarex. Сейчас preview/dry-run только показывает план перемещения. Рабочий `-load` пока заблокирован и эту подпапку не создаёт. Ошибки маршрута и даты не равнозначны отсутствию номера в Excel.

Для проверки `-fill` сначала самостоятельно сделайте копию Excel и укажите путь к ней. Уже заполненные URL не заменяются. PDF для `-fill` не нужны. Несовпадение даты, несколько строк-кандидатов, неизвестный маршрут и дубликат — причины пропуска, а не повод выбирать приблизительное совпадение.

## Полная имитация загрузки без Sarex

После первого запуска `start.py` на macOS:

```sh
.venv/bin/python tools/mock_demo.py my-mock-test-01
```

Используйте каждый раз новую папку результата. Скрипт создаёт только синтетические Excel/PDF и новый SQLite-журнал. Сетевые обращения запрещены. Проверяется рабочая цепочка с mock API: один новый документ, два локальных дубликата, сохранение URL и повторный запуск с нулём новых отправок. Это проверка механизма, а не покрытия ваших реестров. Полная mock-цепочка сейчас требует macOS/Linux; Windows проверяется отдельно по компонентам.

Для проверки реальных данных без отправки используйте `-preview sk` или `-preview vk`: это чтение настоящего дерева и расчёт назначений, без имитации успешной отправки.

## Команда тестового PDF (macOS/Linux)

```sh
python3 start.py -test-pdf
```

Авторизация и GET проверяют 99-Тест. Программа сама создаёт один небольшой синтетический PDF и согласованный Excel. Команда ничего не отправляет, показывает имя, цель и SHA-256 плана. Цель фиксирована: `99-Тест`, корень `2093037`, папка `7915046`; выбрать другую папку нельзя.

Только когда вы готовы разрешить реальную запись этого PDF:

```sh
python3 start.py -test-pdf --send ХЕШ_ИЗ_ПРЕДЫДУЩЕЙ_КОМАНДЫ
```

Вместо заглушки вставьте выведенный хеш. Программа повторно проверит цель и дубликаты, покажет имя и попросит ввести `да`. Максимум один новый документ, никаких папок. После отправки — GET-проверка, URL в новый тестовый Excel и сохранение SQLite. Повтор той же команды использует тот же PDF/журнал и не создаёт документ повторно. Найденный чужой дубликат блокирует отправку. При UNKNOWN программа остановится без повтора POST.

Состояние хранится в `~/.sarex-loader-synthetic-test` независимо от распаковки новой версии. Не удаляйте и не переносите эту папку ради нового теста. При изменении плана после обновления программа может потребовать разбор вместо повторной отправки. Старые журналы других тестов не затрагиваются.

Ограниченный режим проверен на mock HTTPS. Пользователь подтвердил успешную реальную отправку этой командой в 99-Тест; повтор нового теста ещё нужно подтвердить по журналу. Он не принимает клиентские PDF. Windows-отправка пока явно заблокирована до переноса всей цепочки upload. Старый `-load test` остаётся внутренним историческим режимом.

## Windows и GitHub Actions

Нативная Windows-проверка ещё не завершена. Подготовлен ручной workflow **Windows and macOS validation**:

1. Отправьте изменения в ветку `main`.
2. GitHub → Actions → Windows and macOS validation → Run workflow → main.
3. Дождитесь двух задач `validate` и задачи `compare`.
4. После успешной проверки в артефактах будут также ZIP, установленные и проверенные на соответствующей ОС. При ошибке скачайте артефакты `validation-windows-latest` и `validation-macos-latest` и передайте диагностику разработчику.

CI также собирает ZIP соответствующей ОС и проверяет чистую установку из архива, `-help` и блокировку производственного `-load`. На Windows проверяется запуск `start.bat`.

Runner получает только разрешённые исходники и синтетические тесты, без `account.toml`, клиентских документов, истории Git и исторических SQLite. Проверяются нативный Python, CLI, кириллица, Excel, перемещения синтетических файлов, SQLite/блокировки/сбой/повтор и равенство результатов двух ОС. Зелёный CI подтверждает только перечисленные проверки: полноценный Windows-upload ещё содержит ограничения POSIX и не считается принятым.

## Ограничения и восстановление

- Создание месячных папок выключено; отсутствующая папка означает пропуск с причиной.
- `OUTCOME_UNKNOWN` останавливает опасные операции. Не повторяйте неопределённый POST и не сбрасывайте журнал.
- Не удаляйте журналы, checkpoint и резервные копии ради «чистого запуска».
- В диагностике PDF не перемещаются. Служебные подпапки не используются как новые входные файлы.
- Не публикуйте конфиг с учётной записью, клиентские данные и журналы в открытом репозитории или открытом релизе.
- Последний полный локальный прогон имел один нестабильный тест защитного preflight; отдельные повторы проходили. Это остаётся пунктом приёмки, а не доказанно исправленной ошибкой.

## Сборка предварительного релиза

Инструкция публикации и текст описания находятся в `RELEASE_NOTES.md`. Клиенту передавайте специально собранный ZIP, а не автоматический GitHub Source code: в ZIP нет тестов, исторических отчётов, журналов и клиентских файлов. Включены README, программа, маршруты и запускатели.

## Результаты и журнал

Папка результатов больше не запрашивается. Программа создаёт в `Downloads` новую папку `отчет-ГГГГ-ММ-ДД-ЧЧ-ММ-СС` (при совпадении времени добавляет номер). Сначала откройте `ИТОГИ.md`, затем подробный Markdown и CSV. Повторяющиеся сообщения записываются в `журнал.txt`. После успешного завершения снимки дерева, планы и checkpoint упаковываются в `технические-данные.zip`; резервные копии Excel остаются отдельно. При сбое технические файлы не упаковываются и не удаляются: checkpoint можно использовать с `--resume`. Исторические результаты не меняются.

Чтобы изменить базовую папку, добавьте в начало `account.toml`, **до `[auth]`**, строку (папка создаётся автоматически):

```toml
results_dir = '/Users/имя/Downloads/Отчёты Sarex'
```

На Windows, например: `results_dir = 'C:\Users\Имя\Downloads\Отчёты Sarex'`. Это абсолютный локальный путь; выбирайте место отдельно от каталога исходного Excel и папок PDF. Без этой строки используется домашняя папка `Downloads`. Повторная настройка аккаунта сохраняет выбранное расположение отчётов.
